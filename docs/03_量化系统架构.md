# 量化系统架构：网页回测工作台

> 状态：目标设计待评审，网页和实验服务尚未实现。

## 系统目标

近期交付目标是可供用户与 Agent 共同使用的完整回测工作台：在网页中准备数据、编辑策略代码及参数、运行回测、查看过程、分析结果并比较不同实验。详细设计与验收要求见 [工作台架构设计](planning-artifacts/architecture.md)。

首版方案按本机单用户设计，Python 服务配合浏览器前端；部署方式尚待确认。交易范围为 A 股场内股票型行业 ETF 的日线、多头和现金账户，策略逻辑可更换，主线中期趋势只是其中待验证的研究方案。系统正确性与策略盈利能力分别验收。

## 目标分层

```text
浏览器 / Agent API / CLI
          ↓
统一应用服务：策略修订、数据版本、实验配置、任务管理
          ↓
不可变运行快照 → 独立 Python 工作进程
          ↓
策略接口 → 每日风险检查 → 订单与撮合 → 现金持仓账本
          ↓
进度与事件、指标与曲线、结果明细、实验比较与导出
```

推荐 FastAPI + React/TypeScript，SQLite 保存任务与索引，本地文件保存代码、数据和产物。前端构建后由 Python 服务同源提供；回测独立进程运行，默认单任务并发，其余排队。网页刷新不影响任务，Agent 与网页共用同一服务和回测口径。

## 策略与回测边界

策略声明参数契约、必要数据、预热长度和评估日程，接收决策时点可得数据及真实持仓状态，返回目标组合或明确的保持指令。空目标表示全部现金，与未发起调仓区分。策略可以改变因子、筛选和持仓逻辑，不得直接修改成交、费用、现金和净值。

引擎统一处理交易日历、先卖后买、成本、现金约束、订单未成交、日风险检查和估值。收盘决定最早在后续可交易时点执行，不能使用同日收盘价决定开盘订单，也不能让收盘风险信号回填成交。持仓失去新增资格时仍须计价与管理，停牌或数据异常不能使其价值凭空归零。

风险配置是显式的实验假设，变更时形成新运行；研究比较不代表批准真实账户风险。VaR、波动和回撤触发器都不保证实际损失上限。真实账户治理仍以 [交易宪法](../notes/交易宪法.md)为准。

## 数据、快照与任务

统一 CSV/Parquet 数据契约，明确行情来源、历史池、基准、时间覆盖、复权/分红及交易状态。数据获取、导入、校验和版本注册均能从网页发起。旧的前复权日线可用于显式标注的简化研究，不能无提示地当作真实成交价格。成分广度等缺少数据的研究保持未验证状态。

每次运行冻结策略源码、有效参数、数据版本、引擎源码、依赖环境、种子和评价口径。修改草稿不改变已经排队或完成的运行；历史结果不可覆盖。复现时校验快照及环境，不满足条件时明确说明差异。

任务持久记录排队、运行、成功、失败、取消和中断状态，提供模拟日期、进度、日志及错误。取消请求与实际停止分开；服务重启后不能把中断运行当作成功，也不静默续算。首版执行受信任本地策略代码，子进程不是恶意代码沙箱。

## 网页结果与比较

网页包括数据集、策略与实验编辑、运行列表/详情以及多实验比较。运行详情能追溯信号、目标、风控调整、订单、成交与每日持仓，而不只显示收益数字。

结果包含净值及基准、回撤、年度/月度收益、仓位、现金、换手、费用和可筛选明细，并可导出 CSV/JSON 和独立 HTML 报告。不同数据、区间、基准和成本口径的差异在比较中明确显示；不自动裁切并给出误导性优劣排序。

## 当前状态与交付顺序

现有仓库只有数据获取、pandas 回测及 CSV/JSON/Markdown 报告原型。新系统需要先修正交易时点、缺价估值、空目标、现金分配、配置生效和结果覆盖问题；不能只在原有回测外加页面后宣称完成。

交付顺序为可信回测内核 → 实验运行服务与 Agent 接口 → 网页完整闭环 → 安装启动及故障路径验收。每个可检查阶段验证后独立 commit。首版不包含自动下单、多人平台或分布式计算。
