# 回测工作台使用指南

首版在 Windows 本机单用户环境验收。回测覆盖 A 股场内股票型行业 ETF、日线、多头现金账户。系统流程正确不代表策略盈利或具备实盘条件。

第一次使用时，先阅读[工作台入门与完整讲解](00_工作台入门与完整讲解.md)，理解数据、策略、实验与运行的关系，再按下面的步骤操作。

## 安装、启动与文件

代码已合入 `v2`，主工作目录为 `D:\Projects\quanto`，以下命令均在仓库根目录执行。工作台需要 Python 3.13、Node.js 24、uv，以及锁定的 Python 和前端依赖。

```powershell
uv sync --locked --extra dev --extra web --extra data
npm.cmd --prefix web ci
npm.cmd --prefix web run build
.\scripts\start-workbench.ps1
```

打开 <http://127.0.0.1:8765>。脚本先检查锁定 Python 环境和前端依赖；CLI 对 `web/dist/build-manifest.json` 中的源码/构建产物 SHA-256 做一致性校验，再绑定一个端口，启动一个调度器。`FRONTEND_BUILD_INVALID` 请重新执行 `npm.cmd --prefix web ci` 和 `npm.cmd --prefix web run build`；`DEPENDENCIES_MISMATCH` 请执行提示的同步命令。`PORT_IN_USE` 请停止原服务或明确选用另一端口，不会静默重试或另开开发服务器。

若保留已有 `8765` 服务，可以在主目录启动另一端口：

```powershell
.\scripts\start-workbench.ps1 -Port 8767
```

此时访问 <http://127.0.0.1:8767>；下文 API 示例中的端口也要相应替换。Agent CLI 的地址参数放在子命令之前，例如 `uv run --no-sync quanto --url http://127.0.0.1:8767 datasets list`。

等价直接命令：

```powershell
uv run --no-sync quanto serve --host 127.0.0.1 --port 8765 --workspace data/workbench
```

默认 `data/workbench` 保存 SQLite、会话令牌、版本与快照；默认产物在 `outputs/workbench/<job_id>/final`。首次创建时把产物根路径写入 `workspace.json`；任意 `--workspace` 默认在其自身 `artifacts` 下保存产物。可在停止服务后配置新任务的产物根目录；已创建任务保留自己的记录路径，不随配置移动。不要提交数据、令牌、快照或产物。关闭前台服务使用 Ctrl+C，重启使用同一命令；刷新网页不会停止后台任务。

Git 合并带回源码与文档，不会自动迁移被忽略的数据库、数据、运行报告、依赖目录或前端构建。2026-09-30 的 `8765` 预览已使用主仓新源码和前端，但保留旧 worktree 的解释器及工作区，以保留历史记录和精确重跑环境。该目录仍在使用，不要归档；现有预览的重启命令见[切换记录](superpowers/plans/2026-09-30-preview-cutover.md)。上述默认启动命令会使用主目录自己的工作区，首次可能没有旧运行；不要在服务运行中搬动数据库和产物。

所有服务地址须为回环地址。网页静态导航和资源经过 Host/Origin 检查，`/api/session` 提供令牌，其他 API 需 Bearer；深链接如 `/runs/<run_id>` 可直接打开或刷新，未知 `/api/*` 返回 JSON 错误。仅可信本机软件应访问会话接口。首版不是远程服务或多用户权限系统。

## 首次完成一次回测

1. 在“数据版本”获取 ETF 真实行情，或导入符合契约的 ZIP。等待校验和登记完成后，检查版本实际覆盖、标的和限制；覆盖不完整时先处理数据问题。
2. 进入“策略与实验”，选择一个策略模板和刚登记的数据版本。`trend_rotation` 需要足够的预热历史；模板只是可编辑起点。
3. 从该版本的实际覆盖中选择标的和回测日期，填写用途及初始资金（例如 `100000`），逐项检查费用和风险假设后保存实验。
4. 可编辑 `strategy.py`、`strategy.json` 和声明的辅助 Python 文件；“保存新修订”只登记不可变源码，再用“验证当前策略与参数”运行协议验证。参数表单由 schema 驱动，未知参数会被拒绝；保存实验后可查看服务端解析的默认参数。
5. 进入“回测任务”，选择实验并运行。独立工作进程推进交易日，其他任务排队；详情显示日志、完整交易日进度、订单、成交、持仓和最终报告。无交易但有有效评估也是合法现金报告。
6. 在要分支的运行详情点击“从此历史运行创建实验”，用当时冻结的有效配置创建独立草稿，修改代码或参数并保存后再运行。草稿页“克隆为新实验”只复制当前编辑内容。对比页填入两个运行 ID；页面列出冻结输入差异，仅对直接可比运行叠加曲线，不截取日期或重算指标来制造可比性。
7. 成功详情可下载 CSV 明细 ZIP、JSON 报告 ZIP 和独立 HTML。HTML 可离线打开；ZIP 清单描述完整报告，可能列出该格式子集包没有包含的文件。

一次最多提交 100 组有限参数列表。每组独立草稿与运行，整个批次冻结后原子入队；这不是同时运行 100 个进程。重试已准备的提交沿用同一幂等键，不额外创建运行。

## 按需查看回测结果

运行列表优先显示冻结的策略名称、回测区间、初始资金，以及累计收益、年化收益、最大回撤、夏普比率和最终权益；正收益用红色、负收益用绿色。演示数据和价格口径保留醒目标记。运行编号、实验及版本 ID、完整有效参数、样本用途和来源说明收进“参数与来源”，可直接在列表展开。未成功完成的运行只显示状态和已完成日期，不展示最终绩效。修改实验或保存策略新修订不会改变旧运行的摘要。

进入详情时，先读取最终指标、当前图表摘要、最近 100 条日志，以及最近完成交易日的账户和交易追踪。页面不会一次下载整个回测期间的持仓、订单和成交历史。

运行列表和详情中的提交、开始、结束时间统一按北京时间（Asia/Shanghai，UTC+8）显示；存储和 API 保留原始 UTC 时间。模拟日期、已完成交易日以及明细日期属于回测历史日期，不随任务时区换算。

“账户与交易明细”默认显示最近交易日。可选择“最近30天”或“全区间”，也可填写开始、结束日期及标的后点击“查询明细”。切换页签才查询对应表；每页最多 100 行，通过上一页、下一页查看，并显示筛选后的总行数。订单按信号日、成交按成交日、FIFO 片段按平仓日、未平仓批次按建仓日筛选。账户、策略信号和风控属于全局记录，标的筛选不排除它们。

“交易决策追踪”按单日查询，四类记录分别分页。“前一天 / 后一天”按自然日切换并直接查询，保留当前标的筛选，换日后从第一页开始；到回测起止日期时，对应方向禁用，非交易日可能没有记录。服务端关联该日信号及执行订单，并补充对应信号日期的上下文；成交仍通过 `order_id` 关联。关联信号或订单未在当前页显示时，页面会说明，不能把当前页没有记录解释成不存在关联。

“绩效图表”只请求当前页签的数据，可另选日期区间。每个视图最多 1200 个点，曲线保留端点及分桶极值；持仓权重按完整日期取样，选中的日期保留全部标的。页面说明是否采样，展开的是图表数据。对比页也使用每个运行的有界摘要，展开时选择一个运行查看。累计收益、最大回撤等最终指标仍来自完整报告，不用图表样本重新计算；完整历史通过明细分页或导出查看。

每块区域分别显示加载中、加载失败或确实没有记录。暂时性网络和服务错误最多尝试三次，可点击该区域的重试按钮；日期、标的或页签改变时会中止旧请求。回测结束后，当前明细会从部分结果重新读取最终结果。

已完成结果首次查询时，系统从校验通过的冻结产物逐行建立 `result-indexes/` 下的 SQLite 查询副本，包含日期、标的和订单关联索引及图表摘要缓存。后续查询直接筛选并读取当前页；服务重启可复用副本，不再每页解析整张 CSV。查询副本是可重建的派生数据，冻结 CSV/JSON/HTML 继续作为完整导出及来源凭据；源文件内容校验仍保留。首次建立副本会比后续访问慢。

建库完成后会生成 SQLite 索引统计信息，帮助数据库选择日期或标的联合索引；图表摘要按查询参数保存，每个运行最多缓存 64 组，损坏的摘要会重新计算。运行中的明细直接在部分结果数据库中按索引分页，不把全部部分结果读入内存；近期日志从文件尾部读取完整事件，并仅返回明细行数摘要。

本次多年回测的查询规模和耗时见 [结果查询验收记录](superpowers/benchmarks/2026-10-01-result-query.md)。其中首次建库与后续分页分别计时，实测数据不构成所有规模下的响应时间保证。

## 数据导入与真实来源限制

网页上传 ZIP，根目录含 `manifest.json` 及六张基础表，每表只能提供 CSV 或 Parquet 一种。新登记的版本在完整验证后统一保存为 Parquet；输入文件、已有版本和历史快照不会被覆盖：

| 表 | 必要字段/含义 |
|---|---|
| prices | date, symbol, open, high, low, close, volume, amount |
| benchmark | date, close, turnover；声明指数口径与成交额含义 |
| calendar | date；完整市场交易日历，覆盖预热及评估末端判断所需后续交易日 |
| instruments | symbol, lot_size, settlement_sessions, listing_date, group |
| status | date, symbol, status, can_buy, can_sell；显式交易/停牌状态 |
| events | symbol, event_type, record_date, ex_date, pay_date, cash_per_share, split_ratio；没有事件也保留表头 |

代码按字符串处理，保留前导零。清单包括 source、is_demo、price_mode、currency、calendar_start/end、data_start/end、volume_unit、amount_unit、event_coverage、benchmark_type、field_semantics、universe_rule、limitations；附加研究表通过 auxiliary_tables 声明相对路径，可在 ZIP 内按声明嵌套，不能夹带未声明文件或目录条目。完整机器契约见 `src/quanto/data/schemas.py` 与 `src/quanto/data/loaders.py`。预检只查看声明；独立导入任务验证实际数据、哈希和覆盖后才登记版本。

`raw_cash` 使用未复权价格和完整事件/状态，分红分别处理应收与支付，拆分调整数量和成本。`adjusted_research` 使用显式简化研究价格，不再叠加现金分红；必须显示限制，不等同真实成交。qfq 行情的每手、结算周期、交易标志、首次观测日等可能只是合成研究假设；成交量/额单位未核实，不能据此运行依赖绝对单位的筛选。未知缺价不能视为停牌或自动补齐；已确认停牌按配置陈旧上限计价，超限明确失败。

2026-09-29 的有限联网检查中，ETF `512480` 返回 `2024-01-08..12` 全部五个请求交易日，但默认 `sh000300` 基准出现 `ConnectionError`，最终 `incomplete / COVERAGE_INCOMPLETE`，未登记数据版本。不能据此宣称真实获取完全可用，也不能说没有做过联网检查。没有替换基准来制造成功；演示和用户导入是已验收的独立路径。

## 数据复用与备份

SQLite `workbench.sqlite3` 管理任务及版本索引；新数据版本中的六张基础表和声明的辅助表保存为 Parquet。辅助表文件名在登记时规范化，使用版本 manifest 中的映射读取。原始获取缓存仍为按标的 CSV，回测报告继续提供 CSV/JSON/HTML 导出。

新运行采用快照 schema v2：`snapshots/<run_id>` 保存策略、引擎和输入清单，`dataset_ref` 指向同工作区 `dataset_objects/<content_hash>` 的共享数据。首次使用时原子发布，后续复用；同批次相同版本只准备和结构验证一次。原 schema v1 运行保留嵌入数据、校验、克隆及重跑路径，原字节不修改。

回测读数前仍校验对象的完整文件集合和哈希；对象缺失或被修改会明确失败，不自动改用最新数据。规范 Parquet 在读取时过滤所选标的及结束日，保留所有起点前历史、完整交易日历及需要的事件/辅助表。旧 CSV 数据版本可以继续运行，但 CSV 的过滤在整表读取后进行。旧 Parquet 如果将日期存为文本或代码存为数字，也会先完整读取并规范类型，再筛选，以保留原有语义。

完整备份需在停止服务后同时保存工作区根目录（包括数据库、数据版本、共享对象、策略和快照）及 `workspace.json` 指定的产物目录。单独复制数据库或某个 v2 运行目录不能独立恢复回测。数据库已有绝对路径，跨目录迁移需要同步处理路径引用；本次没有加入自动迁移或对象清理。不要手动删除仍被历史运行引用的共享对象。

## 时序与模型假设

收盘决策只使用截至当时已知的历史；常规订单只参加指定的下一交易日开盘撮合，余量到期并记录原因，数日后不会自动补买。卖出先于买入，现金不足按规则分配；未列入完整目标的已有持仓目标为零，`Hold` 则没有新的常规目标。

分红须满足 `record_date < ex_date <= pay_date`。例如 1 月 8 日登记、9 日除息、12 日支付：8 日收盘按成交后持仓固定权益，9 日开盘前记应收，12 日才转入现金；起始日之前没有持仓权益。拆分在生效日开盘前处理持仓、未结算份额和有效订单；不支持无现金补偿说明的碎股份额。完整退出可卖出拆分后的全部整数零股，部分减仓仍遵守每手规则。

现金利息基数是日初事件入账后的可用现金、开盘成交之前的余额，收盘入账；例如当日卖出收入从下一交易日起计息。恢复批准须在决策时点已知，绑定当前暂停，使用一次后消耗；只在风险限制通过后重置该次风险回撤参考，不抹去历史绩效回撤。

通用预检只验证预热历史机会；自定义 `should_evaluate` 可以依赖实时组合/风险状态，实际日程由运行时判断。没有任何可评估的预热后交易日会失败，评估有效但无交易则有效。完整往返按单标的空仓→持有→空仓计数，FIFO 匹配片段不增加往返次数。任意整数种子保留给 Python random，NumPy 与 PYTHONHASHSEED 使用模 `2**32`，因此部分不同整数会在后二者中碰撞，派生值写入运行元数据。

## API 与 Agent CLI

启动服务后，在 PowerShell 读取本机会话令牌（不要分享或提交令牌）：

```powershell
$session = Invoke-RestMethod http://127.0.0.1:8765/api/session
$env:QUANTO_TOKEN = $session.token
$headers = @{ Authorization = "Bearer $env:QUANTO_TOKEN" }
# 演示数据任务仅供开发与自动化测试
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/api/jobs/data -Headers $headers -ContentType 'application/json' -Body '{"kind":"demo","payload":{"years":1,"seed":7}}'
uv run --no-sync quanto datasets list
uv run --no-sync quanto strategies list
uv run --no-sync quanto experiments create --json experiment.json
uv run --no-sync quanto runs submit --json submit.json
uv run --no-sync quanto runs get <run_id>
uv run --no-sync quanto runs logs <run_id>
uv run --no-sync quanto runs results <run_id>
uv run --no-sync quanto runs clone <run_id>
uv run --no-sync quanto compare <run_id_1> <run_id_2>
```

示例 `experiment.json`（替换两个已登记 ID，并按数据实际覆盖填写日期和标的代码）：

```json
{"payload":{"strategy_revision_id":"<strategy_id>","dataset_version_id":"<dataset_id>","strategy_params":{},"sample_purpose":"研究","backtest_spec":{"start":"<覆盖内起始日>","end":"<覆盖内结束日>","symbols":["<覆盖内标的代码>"],"initial_cash":100000,"seed":7,"execution":{"model":"next_open","commission_rate":0,"minimum_commission":0,"slippage_rate":0,"max_stale_sessions":0},"risk":{"max_total_weight":1,"max_symbol_weight":1,"group_caps":{},"stress_scenarios":[],"pause_action":"block_new","recovery_mode":"never"},"metrics":{"annual_sessions":252,"risk_free_rate":0,"cash_rate":0,"definition_version":"1"}}}}
```

`submit.json` 为 `{"experiment_id":"<experiment_id>","expected_revision":1,"idempotency_key":"unique-request-key"}`。修改提交内容必须换键；网络重试应复用原键。策略注册 `POST /api/strategies` 的 `manifest` 必须与 `files["strategy.json"]` 完全一致，`files` 同时含入口/声明辅助源码文本。实验更新 `PUT /api/experiments/<id>` 传 `expected_revision` 与 `payload`，冲突返回 409。列表通过 `next_cursor` 翻页；具体请求契约见 `src/quanto/api/routes.py`，FastAPI `/docs` 提供接口概览，实际调用仍需令牌。

## 失败、取消、重启与复现

失败详情保留稳定错误码、日志、完整交易日部分结果；失败/取消/中断没有成功的最终绩效。取消后先显示等待取消，直到工作进程及所拥有的子进程停止才终结；不要手改 SQLite 状态。重启会恢复队列、将不可继续的旧运行明确中断，不静默续算。

要修正失败输入，可从该历史运行创建实验，修改后创建新运行；要重跑原快照，使用 `quanto runs rerun <run_id> --json rerun.json`，文件为 `{"idempotency_key":"new-replay-key"}`。旧产物不覆盖。环境不匹配时先阅读差异，恢复原环境再精确重跑，或明确创建记录新环境的新实验，不伪装为精确复现。

快照校验冻结数据、策略/辅助源码、引擎与项目依赖声明/锁文件的字节哈希，并保守核对全部已安装发行包名/版本集合。即使无关包变更也可能阻止精确重跑；第三方包安装文件没有逐一哈希。动态导入和外部读文件不能自动完整发现，可见情况会标记非精确边界。策略是受信任本地 Python，进程隔离与取消不是恶意代码沙箱。

Windows 已验证 Job Object 内核所有权在服务或工作进程异常退出时回收其策略辅助进程；分配受限时在策略执行前失败，不静默降级。非 Windows 仅有现存进程树清理，两个根进程都消失后存在任意辅助进程遗留窗口，没有跨平台同等保证。

图表按需加载 ECharts。当前 chartEngine 构建约 623.28 kB（gzip 211.37 kB），Vite 大块提示保留；首次滚动到图表需要加载该块，具体本机验收时间见实施计划，不代表所有设备性能保证。长序列可视觉降采样，完整明细和后端指标不受影响。

## 冻结来源与结果解释

`POST /api/runs/<run_id>/clone` 与 `quanto runs clone <run_id>` 使用同一服务：验证原运行冻结文件，使用不可变策略/数据 ID 和当时有效参数、完整配置创建草稿；`source_run_id` 传入后代运行的 `parent_run_id` 与来源。它是可编辑分支，不是旧引擎的精确重放。原运行文件不修改。

比较显示完整有效回测配置，以及标的池、初始现金、评估与现金利息、执行/风控定义版本等差异。标的池、初始现金或策略参数不同仍可并列比较；现金利息、评估或执行口径不同不能被判断为相同口径。页面只格式化已计算的百分比、金额和比率；原始值保留在完整详情、图表数据和导出中。

新报告结构版本为 `2`，严格校验文件、哈希、列及来源元数据；历史版本 `1` 仍按旧列严格读取/导出，未知版本拒绝，不改写旧产物。新运行的 `signals` 每个日期保存策略原始 `intent/weights/reasons/diagnostics`，以及独立 `approved_*` 风控批准目标。订单只使用批准目标。风险暂停时仍保留原始诊断。旧运行若没有批准字段，界面明确其原始信号不可证明，不补造历史数据。演示标记和数据来源取自冻结清单，运行摘要、绩效及比较持续展示；新 CSV/JSON ZIP 元数据和独立 HTML 也保留该标记。旧导出保持原字节，不追写新元数据。

保存时可继续编辑；先前请求返回不会清除较新的修改，实验使用返回的最新修订继续保存。源码注册返回若已有新编辑，保留当前缓冲区并说明已注册的是提交时版本；切换草稿/修订后忽略旧响应。schema 枚举保留整数、布尔和空字符串，默认未设置与空字符串不同。

声明研究文件并冻结其字节只提供复现边界，不提供任意辅助表的通用时点查询接口。首版 StrategyContext 的行情/账户/资格/风险状态接口不因注册文件而自动扩展；更广的研究表访问需要后续数据访问扩展。


当前草稿的“克隆为新实验”在策略源码未保存时禁用；先保存策略新修订，或切换草稿并确认放弃源码修改。仅实验配置未保存时仍可克隆；历史运行分支继续使用冻结源码。
