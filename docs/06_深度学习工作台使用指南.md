# 分钟数据深度学习工作台使用指南

工作台的“深度学习”页面提供分钟数据准备、线性/GRU 训练、模型登记、冻结模型回测及基础对照。它是独立的盘中研究流程，与原有 ETF 日线策略工作台共用行情库和任务队列。运行成功说明软件闭环可用，不代表策略盈利、可交易或达到实盘条件。

## 安装与启动

在仓库根目录使用 Python 3.13、uv、Node.js 24：

```powershell
uv sync --locked --extra dev --extra web --extra data --extra learning
npm.cmd --prefix web ci
npm.cmd --prefix web run build
.\scripts\start-workbench.ps1
```

访问 [深度学习页面](http://127.0.0.1:8765/learning)。使用其他端口时相应修改地址。依赖中的 PyTorch 从仓库配置的 CUDA 12.8 wheel 源安装；CPU 也能运行同一安装。日线流程不需要安装 `learning` extra。实际依赖以 `uv.lock` 为准，本机验证记录见[验收记录](research/2026-10-03-deeplearning/acceptance.md)。

先在概览查看 PyTorch、CUDA、设备名称和磁盘剩余空间。`auto` 根据实际可用设备选择并记录；指定 `cuda` 后若不可用会失败。CUDA 内存不足时降低 `batch_size`、`lookback`、`hidden_size`，或明确重新提交 CPU 配置；不会静默降级。GPU 能执行不保证小模型比 CPU 更快，准备数据和窗口仍使用 CPU/磁盘。

## 获取真实分钟快照

**目前 AKShare/Tencent 在线适配器只提供日线；点击原日线数据获取不会取得分钟行情。真实 1 分钟数据需要从有权限的来源显式导入。** 页面没有快照时，先完成以下流程。合成验收脚本仅用于开发验收。

1. 将供应商数据转换成 CSV/Parquet，列包含 `instrument_id,trading_date,bar_start,bar_end,open,high,low,close,volume,amount`。标的例如 `SZSE:etf:159915`，保留代码字符串。`bar_start/bar_end` 是有时区时间，单根为 `[bar_start,bar_end)`，1 分钟必须确实是一分钟。`trading_date` 是当地交易日；不是将 UTC 日期盲目转换成交易日。
2. 根据[分钟导入元数据模板](../examples/learning/minute-import.metadata.json)填写完整请求范围、来源、下载时间、价格口径、成交量/额单位和未知限制。模板内来源必须替换成真实、有证据的来源。无时区原时间列提供 `timezone: "Asia/Shanghai"`，不要给已经是 UTC 的数字重新加上海时区；字段映射用 `column_map`，代码映射用 `instrument_map`。
3. 导入同期交易日历，含 `trading_date,session_start,session_end`，每个交易时段单独一行，例如上海 09:30–11:30 和 13:00–15:00。使用[日历元数据模板](../examples/learning/calendar-import.metadata.json)，按真实节假日/特殊交易时段填写。日历关系决定聚合边界和 T+N 结算；未提供的停牌/涨跌停/公司行动等事实应列入限制。
4. 将[完整需求模板](../examples/learning/minute-requirement.json)调整为实际覆盖，再运行预缓存。导入只登记片段；只有完整需求成为 `ready` 并返回快照 ID，才能用于准备训练集。覆盖不完整先修正源数据/日历，不要把缺口补成虚构分钟行情。

```powershell
uv run --no-sync python -m scripts.import_market_data --input D:/minute/159915-202401.csv --metadata minute-import.metadata.json
uv run --no-sync python -m scripts.import_market_data --input D:/minute/calendar-202401.csv --metadata calendar-import.metadata.json
uv run --no-sync python -m scripts.prefetch_market_data --requirement minute-requirement.json
```

脚本使用统一用户行情配置 `~/.quanto/market.json`（本机已配置的共享库），不会通过工作区路径选择另一份真实行情。需要隔离试验时可将 `QUANTO_MARKET_CONFIG` 指向**绝对路径**的独立 JSON，内容为 `{"root":"D:/scratch/market"}`；运行完恢复环境变量。

当前导入器读取一个完整 CSV/Parquet 到 pandas；不是超大文件流式导入。大行情先按“标的 × UTC 月份”分片，每片写准确的请求边界，分别导入，再以完整需求生成快照。原文件字节作为 evidence 保存，会占额外磁盘；快照保留历史版本，准备前要留出原始证据、Parquet、训练特征、窗口缓存和结果空间。分钟特征/标签/权重不写回行情库。

原始价格 `raw` 不是“真实现金账本已验证”的承诺。如果供应商提供研究口径，使用 `vendor_research` 并填唯一 `basis_id`；准备请求必须选已解析的同一口径。复权或未处理公司行动的研究价格不会自动重建分红、拆股和申赎现金流。

## 页面操作

在“深度学习”选择分钟快照和频率，填名称后准备训练数据。支持 1、5、15、30、60 分钟；聚合按每段交易时段起点对齐，只保留完整桶，不跨午休/隔夜，不填补缺口。查看准备详情的原始行数、有效行数、剔除/缺口统计、来源限制及哈希。

准备详情保留交易日历中的 `trading_sessions`，并报告 `expected_minutes`、`missing_minutes`、每标的 `missing_minutes_by_instrument`、同一交易时段内的 `gap_events`，以及 `invalid_rows`、`invalid_feature_bars`、`incomplete_buckets`、`outside_session_rows`。缺失统计与无效行情统计需要一起检查；没有缺失分钟不表示行情值或来源已经核实。

选择训练集，填写三个按时间排列的训练、验证、测试区间，以及模型、窗口、标签跨度、轮数、批大小、学习率、设备和种子。页面时间按上海时间显示/输入，API 保存 UTC；所有区间为左闭右开 `[start,end)`。先尝试线性模型，再与小 GRU 比较，同一数据、切分、标签和成本下才有比较意义。完成后在模型详情查看训练配置、归一化参数、设备运行记录、最佳轮次、损失曲线和预测误差。

任务进入已有监督队列，默认单任务执行。查看进度/日志或取消；服务退出后运行任务标记为中断。只有成功且产物哈希验证通过的任务才登记训练集/模型/回测。

选择登记模型及训练集，在测试段或更晚的独立时间段提交冻结模型回测；选择等权、动量、现金对照时无需模型。详情提供分钟净值、日末净值、信号、订单、成交和持仓；图表有界降采样、表格分页，ZIP 导出完整 CSV 与摘要。日线结果比较接口与这套学习结果分开；比较学习实验时对齐配置并查看其各自摘要/导出。

## 时间切分与标签

特征仅由已完成 K 线及其历史构造。标签为信号 K 线之后的下一根开盘，到 `horizon` 指定未来 K 线收盘的对数收益。只有完整标签终点落在所属分区内的窗口可用；跨训练/验证/测试边界的标签被清除（purge）。后一区间可用之前已经知道的行情预热窗口。不要随机拆分相邻重叠窗口；不要因为分区无有效样本而缩短时间边界掩盖问题，应检查历史长度、缺口、窗口/标签跨度。

当前步数语义显式为 `observed_bar_steps`：`lookback` 和 `horizon` 按该标的实际观察到的完整 K 线根数计数。缺失行情、午休、隔夜可让标签与窗口覆盖的钟表时间变长；例如五根 1m K 线不保证对应连续五分钟。此政策随训练集和模型保存，缺口不会补成合成 K 线。需要固定钟表时长研究时，应先根据完整性统计挑选满足该条件的数据，不能直接把 `horizon` 解释为连续分钟数。

标准化只拟合训练区间；验证集选择最佳权重及早停，测试集只在权重冻结后评估。模型 `cutoff` 为训练/验证截止时间，回测默认拒绝早于它的起点。API 显式 `allow_in_sample:true` 可以做研究重放，结果标注训练区间重叠，不能当成样本外证据。反复用测试集调参数后，该历史已经被研究看过，需要新的留出时间段或滚动前推验证。

## CLI、JSON 与恢复

CLI 和页面使用相同本机 API。先获取本机令牌；换端口时同时修改 `--url` 和 session 地址：

```powershell
$env:QUANTO_TOKEN = (Invoke-RestMethod http://127.0.0.1:8765/api/session).token
uv run --no-sync quanto learning overview
uv run --no-sync quanto learning prepare --json prepare.json
uv run --no-sync quanto learning logs <job-id>
uv run --no-sync quanto learning get datasets <dataset-id>
uv run --no-sync quanto learning train --json train.json
uv run --no-sync quanto learning get models <model-id>
uv run --no-sync quanto learning backtest --json backtest.json
uv run --no-sync quanto learning get backtests <backtest-id>
uv run --no-sync quanto learning cancel <job-id>
```

[prepare.json](../examples/learning/prepare.json)、[train.json](../examples/learning/train.json)、[backtest.json](../examples/learning/backtest.json)是契约模板。必须替换快照/训练集/模型 ID，并调整时间为真实覆盖。全零快照哈希和 `REPLACE_*` ID 没有对应数据，不能直接执行成功。提交返回 job ID；成功登记产物使用同一个 ID。在 `overview` 或日志里确认 `succeeded` 后再引用，提交成功不等于任务执行成功。

每个完整 epoch 保存模型、优化器、随机状态及数据/配置身份的检查点。取消/失败/中断且已有完整检查点的训练任务，可在 `train.json` 顶层加入 `"resume_job_id":"<旧任务ID>"`，保持原训练集与训练配置身份，增加 `spec.epochs` 到大于已完成轮次后重新提交。恢复创建新任务，旧任务保留终态。恢复允许改显示名称和目标轮数；切分、设备、窗口、模型、种子等身份参数必须相同。没有完整 epoch 的任务只能重新训练。

若取消/服务重启恰好发生在工作进程将 staging 原子移到 final 之后、成功登记之前，该任务仍保留取消/中断状态；其中完整 final 检查点也可通过旧任务 ID 恢复。概览中的 `checkpoint_available` 同时识别 staging 和 final 的完整检查点。恢复请求复制已通过哈希校验的当前检查点及其元数据，保留旧任务记录。

克隆/调参可复制模型详情的 `config`，更改名称和指定参数后作为新 `spec` 提交，不加 `resume_job_id`。这是一轮新的训练，保留数据版本、参数和结果，避免反复覆写同一模型。保存的是 `state_dict`，加载显式 `weights_only=True`；改变制品字节会被哈希校验拒绝。确定性设置和种子会记录，但不保证跨硬件/库版本逐位相同。

## 交易假设与结果限制

模型只是收益预测器；排名、再平衡频率、仓位上限、回撤暂停等规则决定实际订单。信号在 K 线完成后生成，下一根可交易 K 线开盘模拟成交；没有“当前收盘价看到信号又成交”的假设。费用含佣金、最低佣金和方向性滑点；现金、整数手数、可卖数量和上一根已完成 K 线成交量的参与率上限限制规模，剩余未成交量到期并记录原因。

`settlement_days` 按交易日推进。T+1 当日买入不能当日卖出，午休和下一分钟不会让持仓解禁。`instruments` 可为每个标的覆盖 `lot_size` 和 `settlement_days`；未核实证券规则时，全局默认只是研究假设，不能机械套用于所有 ETF。请根据实际证券信息填写并保留来源依据。

年化收益和 Sharpe 使用日末净值及交易日尺度，另报告盘中最大回撤。现金利息每交易日一次。短样本年化数字不稳健；预测误差降低不等于扣费交易收益改善。线性模型是预测基线；现金/等权/动量是持仓基线，必须采用同一时段、行情、成本与约束。不要只挑最高净值，检查换手、拒单、实际成交量、回撤和成本敏感性。

回测请求必须处于已准备训练集的查询范围内。任务依据 `trading_sessions`、频率和请求边界派生 `expected_trading_days`：一个时段在请求内至少容纳一根完整聚合 K 线时，其交易日属于必须覆盖的日期。实际观察日期若缺少任一预期整交易日（含首日、尾日），或出现额外日期，回测会失败；避免少计交易日而扭曲利息、结算和绩效。这项检查不证明每个标的每分钟完整，仍须查看缺口和无效数据统计。直接调用引擎时若未提供期望交易日，摘要明确表示首尾交易日覆盖未经确认。

这是 K 线级做多/现金研究模拟，尚未重建盘口队列、成交延迟、真实开盘排队、非线性价格冲击和未知的停牌/涨跌停限制。没有证券事实时有效正 OHLC 被假定可交易，结果会列明假设。研究价格账本不自动加公司行动现金流，不冒充 `raw_cash`。合成价格上的指标仅证明计算流程运行，无投资解释。

## 可复现隔离验收

```powershell
uv run --no-sync python -m scripts.verify_learning_system --device auto --output outputs/learning-verification.json
uv run --no-sync python -m scripts.verify_learning_system --device cpu --symbols 2 --days 5 --epochs 1 --output outputs/learning-cpu-smoke.json
uv run --no-sync python -m scripts.verify_learning_system --device cuda --output outputs/learning-cuda.json
```

默认生成 8 个虚构标的、60 个合成工作日、每天两段 120 分钟，共 **115,200 条原始 1m 行情**；默认在 1m 上训练小 GRU 两轮。可指定 `--symbols --days --frequency --model --epochs --lookback --batch-size --threads --timeout`；`--baselines` 可选择对照，空列表可省略对照。`--temp-parent D:/scratch` 可选择容量充足的临时父目录。每次创建新的子目录，隔离市场配置和工作台，使用 TestClient 及真实监督子进程，不占已有服务端口，不修改现有用户市场库。

成功退出码 0，错误/超时非 0，并写 JSON 记录请求、job ID、来源/模型/结果哈希、运行环境、各阶段耗时、行数、训练误差、回测摘要、导出/查询校验及采样峰值。默认在 `outputs/learning-acceptance` 下建立独立临时子目录，结束后删除行情/权重/结果，仅留记录；加 `--keep-workspace`（等价于 `--keep-artifacts`）保留独立目录用于复查，记录中的路径指向它。报告可覆写，输入/模型内容 ID 可比对；job ID 和临时路径每次不同。

资源采样间隔 0.5 秒，RSS 是父进程及工作子进程的和（共享页可能重复计数），磁盘统计逻辑文件大小，峰值是采样下界；当前未测 GPU 分配峰值，报告明确为 `null`。只能报告实际运行规模，115,200 行验收不证明千万行吞吐或真实行情有效性。
