# 统一行情模块实施与验收

实施分支：`codex/market-data-module`，从已批准设计与计划的 `d613122` 开始。实际测量日期为 2026-10-02。原工作区、已有预览及冻结研究数据未改写。实现使用独立 Parquet 对象、SQLite catalog、不可变 manifest 和来源 evidence；数据来源不会决定目录结构。

## 已实现的边界

- `quanto.data` 自行获取、补缺、刷新、验证、缓存并发布快照，提供同步/异步预缓存、状态、取消、离线查询与 Arrow 批次接口。
- 本地完整数据先于来源能力检查；相同需求共享获取，各请求可独立取消。等待超时不取消获取。跨进程租约检查 owner、generation、expiry，取消与 ready 发布受 catalog 事务约束。
- 回测组装属于 `quanto.backtest`。来源口径、单位未知等限制保留，上市日和交易状态研究假设只进入消费者清单；严格 raw_cash 缺证券信息、真实状态或公司行动时不可执行。
- 工作台任务状态与行情状态独立。已就绪快照及有效数据包都通过父进程校验后，才在同一工作台事务中登记数据版本和来源关系。行情库与工作台库分别有事务边界。
- 旧 V1/V2 运行快照仍依赖自己的冻结数据/共享回测对象，无需连接行情根。旧 CSV 只能显式导入；源字节、字段映射及 SHA-256 保留。旧采集 API 和腾讯目录旁路已移除。
- 当前来源实现为中国市场日线 ETF、指数、日历；在线来源尚未提供可核验复权因子或全部单位证据。分钟数据可离线导入和逐批读取；当前回测引擎仍使用日线。训练特征和张量属于消费者。

## 固定样本测量

复现命令：

```powershell
uv run --no-sync python -m scripts.benchmark_market_data --symbols 32 --daily-days 2520 --minute-days 20 --output benchmark.json
```

机器：Windows 11 10.0.26200，Python 3.13.12，AMD64 Family 26 Model 68，16 个逻辑处理器，约 31.2 GiB RAM。使用 seed 20261001 的合成随机 OHLC、明确的合成交易日/状态/单位事实；分钟每交易日 240 根，含午间休市。另有一个基准与参考表。每项测量一次、未清空 OS 缓存。数值不代表真实来源网络吞吐，也不能作为整体策略回测速比。

完整机器信息、时间、RSS 和实际补缺区间保存在[测量 JSON](2026-10-01-market-data-module-benchmark.json)。对象字节只计当前活动 ETF 行情片段，完整缓存还包含基准、参考表、catalog、evidence、manifest 和保留的旧对象。

测量暴露并修正了两处瓶颈：覆盖检查曾对每个标的重复分组日历；Arrow 逐标量时间转换曾反复查找未安装的可选时区模块。覆盖计算现在复用日历日程，批次比较使用整数纳秒并在 Arrow 内生成 UTC 输出。混合微秒/纳秒分片的回归同时确认时间精度保留。Source 日线日期参数也通过上海交易时区与收盘边界测试，拒绝错误交易所/币种。不同标的可分别解析为不同研究口径，同一标的不兼容口径仍不得拼接。

## 容量外推与 Git

公式为 **标的数 × 每年交易日 252 × 每日 bar 数 × 实测每行对象字节**。以下是活动行情对象的合成样本外推，包含原有 OHLCV/amount/时间字段，不是已获取的数据量，也不含原始响应、额外字段、历史版本、训练张量和备份。

| 标的范围 | 日线行数/年 | 日线对象/年 | 分钟行数/年 | 分钟对象/年 |
|---|---:|---:|---:|---:|
| 32 标的 | 8,064 | 0.51 MiB | 1,935,360 | 112.05 MiB |
| 约 5000 标的 | 1,260,000 | 79.81 MiB | 302,400,000 | 17.10 GiB |

相同字段和压缩条件下，5000 标的十年分钟活动对象约 171 GiB。真实价格分布、字段数量、分片大小和响应格式会改变每行字节。模块保留旧快照与对象，长期多次全历史刷新可使实际空间明显超过活动对象估算；本阶段不做自动回收。分钟片段约每标的每 UTC 月一个文件，大规模还需计入文件数量和元数据成本。

行情根不进入 Git。代码、契约、导入说明和小型来源样本可跟踪；当前已跟踪冻结样本没有被删除。备份需要暂停获取，并复制行情 catalog、manifest、引用对象、evidence，以及工作台数据库、共享回测对象与结果。行情快照与工作台数据版本的来源关系不能代替实际对象备份。

阶段验证包含：完整/筛选历史读取、基准与后续交易日、边界公司行动、辅助数据可知时间、新旧基础表/订单/报告一致性、分钟跨月批次、来源实际 day/qfqday 口径、未知/有证据单位、超时 SDK 子进程回收、两进程租约竞争、取消与发布竞态、异步等待隔离、快照篡改、工作台父进程门槛、旧快照回放、导入与源依赖边界。

初次完整 Python 回归为 364 passed / 1 skipped，随后发现的问题逐项增加回归并修复；最终完整回归与整分支独立审查结果见下方最终记录。Windows 普通会话无法创建符号链接，因此对应权限测试跳过；路径检查的其他测试仍执行。前端完整单元回归为 97 passed，类型检查与构建通过；Playwright 使用已有 Edge，2 个真实后端 E2E 场景通过，包括离线完整与缺失行情。没有把联网采集成功作为自动验收前提。

## 实施裁决

1. 在受管理的独立 worktree 实施，保留原预览和未跟踪 PRD；代价是实现位于单独分支。
2. Windows 上使用 PowerShell/Python 保存任务 brief、BASE 和验证日志；代价是需按 commit 校对 bookkeeping。
3. FragmentRef 组合 DataRequest 与 SourceRecord，避免重复语义字段；代价是内部接口相对计划示例有调整。
4. 日线按单标的语义序列、分钟按单标的月份分片，避免刷新一只标的时退役另一只的缓存；代价是更多小文件。
5. 未核验复权的研究序列扩展重新获取已知历史；原始口径只补实际缺口并保留合并证据；代价是研究来源额外带宽。
6. 来源获取和本地 IO 使用各自有界执行器，等待不占来源 worker；代价是每个池最多 max_workers 个线程。
7. SnapshotRef 公开已解析语义序列和 requirement_key，并增加同步/异步 resolve_snapshot；代价是少量公开元信息，用于正确选口径和父进程验证。
8. 日线消费者声明结束后 14 天的日历需求，组装时要求实际后续交易日；代价是额外日历覆盖，缺失时明确不可组装。
9. 新研究准备入口只导出已提交快照；原 round-two 审核保留为显式只读校验，不复制或重生成历史输出；代价是旧 CSV 须先导入并准备完整需求。
