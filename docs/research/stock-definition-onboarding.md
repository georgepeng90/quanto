# 个股研究接入框架

本框架支持保存少数公司的有序篮子，以及把固定策略和强化学习接到同一套账户、风控和结果流程。当前可执行注册表只有实际实现的 ETF 定义；保存个股篮子不会使 ETF 方案变为个股方案。个股数据、财务特征、策略和学习定义须在后续研究中逐项确定，再以版本化定义接入。合成股票夹具只用于软件测试。

## 研究会话应交付什么

| 研究项 | 必须明确的内容 | 接入位置 |
|---|---|---|
| 选择记录 | 公司范围、入选日期、当时已知信息、增删理由；有序证券身份 | `FrozenBasketRevision`、`selection_note` |
| 数据事实 | 来源证据、许可范围、历史覆盖、更新/重述记录、单位与口径 | 数据版本、`AssetBinding`、表语义绑定 |
| 特征 | 业务意义、计算式、可知时间、缺失处理、预热长度、是否拟合 | `FeatureSetDefinition` |
| 固定策略 | 决策频率、买卖和持有条件、目标仓位、所需特征与交易定义 | 策略修订及 `FixedStrategyDefinition` 声明 |
| 学习方案 | 观察编码、动作空间、奖励、决策时点、训练/验证/测试区间 | `LearningDefinition` |
| 交易规则 | 费用、交易资格、订单有效期、结算、停牌/退市、公司行动 | `TradingDefinition` |
| 验证 | 基线、成本、选择偏差、失败案例、时间稳定性与发布条件 | 测试、研究记录和版本说明 |

不要求所有公司使用相同财务公式。框架要求每次运行能说明实际使用了哪份定义、参数、数据和证据。先完成最小可验证方案；不要以新增字段数量代替研究有效性。

## 身份和数据

1. 使用 `exchange:instrument_type:code`，代码保留字符串及前导零。交易所和证券类别来自可审核来源，不从裸代码前缀猜测。指数用于基准，不能进入持仓篮子。
2. 数据中的局部键与规范证券身份通过不可变 `AssetBinding` 关联。篮子顺序决定模型输入和动作顺序；同一代码在不同交易所或不同证券类别下不是同一资产。
3. 每张表声明结构、语义版本、单位、货币、报告口径和时间规则。基准还需声明价格指数、全收益或其他收益口径，不能仅保留显示名称。
4. 公司报告期、事件生效日、公开披露时间、系统获取时间分别记录。按决策时点先过滤 `available_at`，再选择当时可知的修订；不能用当前修订覆盖全部历史。
5. 披露只有日期时，只有定义明确允许，才采用下一交易日收盘的保守解释。日线收盘 bars 的研究可用性单独声明。未来开盘价格不进入前一日决策。
6. 原始现金口径与复权研究口径不得混用。原始现金口径的拆分、分红、资格及状态需有事实证据；复权口径不能把分红再次记作现金收益。

`RequirementItem` 表达按篮子或参考证券的字段、区间、预热、时间、价格及缺失约束。可选字段缺失不意味着可以跳过已有数据的合法性检查。非价格表的非零预热目前没有通用解释，会阻塞接入，需先研究和实现相应语义。

## 特征和学习

共享 `FeatureFrame` 按证券/字段保留值、缺失掩码、来源及年龄。全局特征单独存储，不用复制到每只证券来掩盖范围差异。账户现金、持仓和奖励状态属于观察编码，不写入市场事实或跨账户缓存。

需要标准化或拟合的方案只用训练段拟合。首个成功策略产物与变换原子发布；失败/取消不形成可引用变换。验证、测试、续训和保存版本回测读取同一冻结变换，不重新拟合。训练区间与数据变化应新建模型，不能伪装为原模型续训。

动作必须明确区分保持、目标组合与全现金。两条决策路径都交给 `SessionRunner` 执行每日风险、订单和账户更新；定义不得另建现金/持仓模拟器。费用只从公开配置中的唯一字段取得。模型回测的成本倍数仅缩放交易定义明确列出的成本项。

奖励是优化信号，净值和利润来自账户。DSR 等奖励不能以利润单位展示。最佳验证权重可以来自之前的会话，末次检查点用于续训，二者来源和步数分别记录。

## 能力、版本与旧对象

先向 `GET /api/definitions` 查询真实注册定义，再提交具体配置给 `POST /api/capabilities/check`。未实现的个股定义、混合 ETF/个股运行、未知身份、时点证据不足或缺数据，应得到字段路径和阻塞原因。能力报告不是提交凭证：提交时服务端会重新解析、冻结并复查。

定义引用必须指定种类、ID、版本；实现和声明变化需要新版本与验证证据。固定策略的参数、学习配置以及交易费用均保持单一来源，公共回测输入禁止额外传入 `symbols`。服务端依据篮子修订和数据绑定生成运行局部键。

旧对象保持原文件及哈希。数据身份关联仅引用已有证据；旧模型仅在已知 ETF 语义和原产物审核通过时增加关联。不能证明的对象继续只读。历史固定回测升级生成带 `source_run_id` 的新草稿；旧实验升级复制指定修订的实际配置，并保存 `source_experiment_ref`。两种升级均需明确选择篮子与定义，不修改原对象。规范键的新数据不能自动投影成旧 checkpoint 的输入键；旧模型的新覆盖回测必须同时满足规范身份与原局部顺序。

## 个股定义登记前的最低验收

- 至少一个可复现的价格路径与公司事实路径；改变未来数据不得改变过去观察、动作和成交。
- 同裸代码不同证券不合并；篮子重排、缺成员映射、基准口径变化均被发现。
- 固定与学习路径接受相同目标时，账户结果一致；保持不引入额外再平衡，日常风险仍运行。
- 停牌、限制交易、拆分/分红、退市或不支持退出事件有明确处理；未知事件不能发布完整成功收益。
- 拟合不接触验证/测试；失败、取消和发布冲突不污染模型头或冻结产物。
- 回测用途明确区分开发回放与后选模回测。手选公司篮子的结果只说明该选择过程，不能直接解释为全市场选股能力；日期在训练后也不自动构成盲测。
- 报告/导出包含有序身份映射、选择记录、数据/定义/代码/参数摘要、能力和限制、训练边界、权重来源；脱离当前数据库仍可解释。

接入审核通过后，才把该实现显式加入注册表。这里没有预设个股买卖条件、财务因子阈值或强化学习奖励配方；这些是下一研究会话的交付内容。
