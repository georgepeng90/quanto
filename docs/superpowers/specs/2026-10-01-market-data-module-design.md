# 统一行情数据模块与预缓存设计

> 历史设计记录。数据根的归属与旧 CSV 退役以[共享行情库修正](2026-10-02-shared-market-library-design.md)为准；旧 `data/raw` 仅是历史来源路径。

本设计将行情获取、标准化、缓存、覆盖检查和数据版本管理收拢到独立的 `quanto.data` 模块。回测、训练、工作台和研究脚本通过同一接口声明数据需求。模块完成预缓存并返回经过校验的固定版本后，需求方才能启动计算；运行期间的数据读取不联网。

用户已确认独立模块、同步与异步接口、不同来源统一组织以及预缓存启动条件。本文件具体化接口、职责、存储和验收条件，供实施前审阅；这里描述目标行为，不表示功能已经实现。

## 当前代码与需要解决的问题

- `data.fetcher` 将供应商访问、CSV 路径、重试、覆盖判断和合并输出放在同一流程中。缓存名称包含调用方提供的 `cache_version`；工作台默认每次生成新 UUID，因此重复任务不能正常复用默认缓存。
- 腾讯采集和标准化分散在 `scripts/fetch_research_tencent.py` 与 `scripts/prepare_round2_market_data.py`，后者直接写入 `data/raw/tencent-20261001`。供应商切换尚未进入统一模块入口。
- 新登记的回测数据已经使用 Parquet；工作台已经有 SQLite、持久任务队列、工作进程、内容哈希和共享不可变数据对象。现有回测运行读取冻结的本地数据，本次保持这一行为。
- 采集任务可以正常结束但覆盖不足，此时不登记数据版本。`jobs.state == succeeded` 本身不能证明数据就绪。
- 当前策略可以访问起点前全部历史；累计历史资格与成交额条件不能仅凭 `warmup_bars` 推导读取范围。
- 当前日线研究源的复权、交易状态、上市日期及单位存在已披露的不确定性。统一目录和字段不会自动消除这些限制。

代码定位：`src/quanto/data/fetcher.py`、`src/quanto/workbench/service.py`、`src/quanto/workbench/data_jobs.py`、`src/quanto/workbench/store.py`、`src/quanto/workbench/dataset_objects.py`、`src/quanto/data/loaders.py`。已有存储工作见 [行情存储与回测数据复用设计](2026-09-30-market-data-storage-design.md)。

## 交付范围

采用项目内独立 Python 模块，延续 Parquet、PyArrow、SQLite 和现有工作台执行设施。模块可以由普通 Python 程序单独使用，不依赖网页、`BacktestSpec`、策略实现或训练框架。

本次实施应覆盖：统一契约、缓存与版本存储、同步与异步预缓存、纯本地读取与批次读取、AKShare 和腾讯日线适配、标准化导入，以及现有工作台和仍承担新采集工作的研究脚本接入。

契约与标准化导入支持 `1d` 和 `1m` 行情。首期联网能力仅承诺已验证的 ETF 日线、指数日线及交易日历；分钟历史来源尚未确定，联网请求应返回能力不足，不能暗中改为日线。分钟数据通过标准化导入与离线样本验证读写、覆盖和批次接口。逐笔、盘口、持续实时订阅及盘中撮合引擎属于后续范围。

特征、标签、选股资格、训练窗口、收益指标和回测账户模型由需求方构建。模块提供行情、标的资料、交易日历、状态和公司行动的事实及其证据，不负责制定研究规则。

保留既有已登记数据和冻结回测记录的离线读取与重跑能力，避免丢失现有研究成果。新采集调用改用新契约，旧采集函数和路径参数不因历史测试继续保留。冻结的历史源文件、研究报告及旧运行快照不就地改写。

## 模块职责与依赖

| 部分 | 职责 |
| --- | --- |
| 公开接口与契约 | 校验需求、返回预缓存状态和版本引用、提供本地查询 |
| 获取协调 | 查覆盖、规划缺口、选择具备能力的来源、限流、重试、并发复用、取消 |
| 来源适配器 | 请求上游、解释响应、转换单位与代码、报告实际价格口径和证据 |
| 质量与覆盖校验 | 检查结构、时间、重复、OHLC、交易时段、缺口和语义冲突 |
| 存储与目录管理 | 发布不可变 Parquet 片段、维护目录、来源记录和版本清单 |
| 本地读取 | 根据已校验版本按标的、区间、字段读取，或按时间顺序返回批次 |

适配器接收标准请求，返回数据、能力与来源记录；它不接收消费者的输出目录，不创建自己的行情库，也不登记实验。工作台负责通用任务执行、进程监督和界面展示，数据业务由模块完成。

回测集的研究假设和策略资格计算留在回测数据组装层。该层使用模块返回的来源和限制生成 `DatasetBundle`，不得把行情存在解释为真实可交易状态。

## 标准数据与身份

`DataRequirement` 包含一组标准数据请求。每个请求声明标的身份、数据类型、频率、时间范围、字段和价格口径。时间范围统一为起点包含、终点不包含的 `[start, end)`；日线调用方把既有包含结束交易日的参数转换为对应完整交易时段。需求还声明所需参考表及质量要求；一个快照必须满足整个需求，不能只准备行情主表。

- 标的身份包含交易场所和标的类型，并通过注册表映射上游代码。ETF 和指数的相同数字代码不冲突；前导零保留。供应商前缀不成为消费者身份。
- 日线、分钟线均采用长表。基础字段为 `instrument_id`、`trading_date`、`bar_start`、`bar_end`、`open`、`high`、`low`、`close`、`volume`、`amount`；频率和价格口径在序列定义中声明。
- 时间戳使用带时区的 UTC，交易日期与交易时段按市场日历解释。标准行情柱使用半开区间 `[bar_start, bar_end)`；上游其他边界表示由适配器转换，闭市成交归属规则在日历和序列元数据中明确。
- 行情序列内键为 `(instrument_id, bar_start, bar_end)`，重复的相同记录去重，不同记录形成冲突。读取排序固定为 `(bar_end, instrument_id, bar_start)`，不能依赖目录遍历顺序。
- 已验证的成交量统一为份或股，成交额统一为声明币种的金额；价格保留足够精度。未知单位保留明确标签，不能当作已完成单位换算。
- 来源记录包含供应商、接口、适配器版本、请求参数、获取时间、上游实际返回模式、原始响应摘要及转换证据。取得时间与行情可知时间分开记录，不用今日下载时间伪造历史公布时间。

实际可知时间有证据时记录 `available_at`；证据不足时保留未知标记及使用的数据可得性假设。不能仅凭 `bar_end` 宣称已验证零延迟可得。参考表和辅助信息同样保留公布与修订信息，需求方按计算时点限制可见数据。

缓存的逻辑序列身份由标的、数据类型、频率、价格口径、币种和标准契约版本决定，不包含任务 ID 或供应商目录。价格口径必须表达原始价格、经验证的复权定义及因子或锚点版本，或明确未验证的供应商研究序列。

未验证复权序列使用带证据摘要的独立 `basis_id`，不能把不同来源的未知口径当成同一序列。来源仍保存在统一元数据结构中，不产生新的来源目录。源切换可以发布不同数据版本，但不能悄悄改变同一版本的内容。

## 统一存储与版本

数据根目录由模块实例配置，普通查询和获取请求不能指定任意输出路径。新行情和原始响应都使用供应商无关的结构：

```text
market_root/
  catalog.sqlite
  objects/<摘要前两位>/<sha256>.parquet
  evidence/<摘要前两位>/<sha256>.bin
  snapshots/<snapshot_id>/manifest.json
  staging/<内部发布标识>/...
```

逻辑分区、标的范围、时间范围、字段统计及来源在目录与版本清单中登记，不要求调用方理解物理布局。首期小规模日线按序列保存完整已知历史；分钟数据按月份保存，并在需要时拆分标的组和文件。不得按供应商建立平行行情库，也不采用每标的每天一个文件的组织。

行情片段不可变，经过标准化、确定性排序和验证后写入暂存区，计算实际文件哈希，再原子发布。版本清单固定引用片段及来源证据，并声明序列、参考表、覆盖范围、契约版本、质量与可得性信息；`snapshot_id` 由清单的规范化内容摘要决定。任务时间和进度不进入内容身份；同一标准需求与同一缓存内容生成同一版本引用。

SQLite 保存序列、覆盖、来源、片段和版本引用。只有文件发布与清单校验完成后，事务才允许把版本标记为可用；失败不得暴露部分版本。先落盘但未引用的完整对象可保留，首期不增加自动垃圾回收。

不同任务或版本复用未改变的片段；刷新生成新片段和版本，不覆盖旧版本。目录可变化，但指定版本的文件集合、来源证据和字节不变。模块负责引用完整性检查，拒绝缺失、篡改、额外文件、非法路径与符号链接；工作台运行快照记录版本摘要。

## 公开接口

下列接口是实施目标，具体类型在模块内定义；同步和异步方法具有相同结果与错误语义。

| 接口 | 返回值与行为 |
| --- | --- |
| `coverage(requirement)` / `coverage_async(requirement)` | `CoverageReport`；仅检查本地覆盖、缺口及质量，不触发获取 |
| `prefetch(requirement, refresh=False)` / `prefetch_async(...)` | `PrefetchTaskRef`；快速提交预缓存，后台执行，不等待整个采集完成 |
| `get_prefetch(task_id)` / `get_prefetch_async(task_id)` | `PrefetchStatus`；进度、覆盖、原因、限制以及就绪版本引用 |
| `wait_ready(task_id, timeout=None)` / `wait_ready_async(...)` | 等待真正就绪并返回 `SnapshotRef`；其他终态返回对应异常和缺口 |
| `cancel_prefetch(task_id)` / `cancel_prefetch_async(task_id)` | 取消该请求及其发布资格 |
| `read_bars(snapshot, query)` / `read_bars_async(...)` | 标准 pandas 长表；纯本地、有范围和字段检查 |
| `read_table(snapshot, table, query)` / `read_table_async(...)` | 读取版本中已声明的日历、标的、状态、公司行动或辅助表；纯本地，不读取任意路径 |
| `iter_batches(snapshot, query)` / `iter_batches_async(...)` | 有界 Arrow 批次的迭代器或异步迭代器；纯本地且全局顺序确定 |

`SnapshotRef` 只包含版本 ID、清单摘要和已声明的覆盖与质量，不提供可写缓存路径。模块从已配置的数据根解析它并核验引用。行情 `DataQuery` 指定一种数据类型、频率和价格口径，只能选择该版本包含的标的、字段和范围；越界以 `DATA_NOT_PREPARED` 拒绝，不调用适配器。参考表查询执行各表明确的区间规则；例如跨边界公司行动和后继日历必须先属于准备需求，不能在运行时扩展。

`DataRequirement` 使用明确的时间区间，不接受含糊的“足够历史”。现有回测组装层根据选定历史数据的起点声明全部历史需求，并包含后继交易日历、基准、状态、跨边界事件及辅助表。未来训练层自行计算输入窗口、标签区间和数据截止要求。

质量要求列出必须验证的事实，例如量额单位、实际价格口径或公司行动覆盖。研究请求可以明确接受特定限制；接受结果携带完整限制。要求已验证事实的请求在相应证据未知时不能就绪。完整行情覆盖不等于完整现金账户回测数据。

```python
task = await market.prefetch_async(requirement)
snapshot = await market.wait_ready_async(task.id)

bars = market.read_bars(snapshot, query)

async for batch in market.iter_batches_async(snapshot, query):
    consume(batch)
```

## 预缓存状态与启动条件

状态流为 `queued -> running -> ready | incomplete | failed | cancelled`。`ready` 必须同时满足完整需求、质量要求、不可变清单发布和引用校验，且有 `SnapshotRef`。其他终态不提供可执行版本。

- `incomplete` 表示源响应或已有数据缺少必需区间、字段、参考表或质量证据，报告具体缺口。
- `failed` 表示任务遇到获取、解析、存储或内部执行错误，报告原因，不把旧的部分缓存标记为就绪。
- `cancelled` 表示请求已取消；模块目录中的请求取消记录在就绪发布事务之前提交则必须获胜。

允许保留已经校验的片段供后续请求复用，但一次失败或取消的请求不能得到 `ready`。如果就绪已经提交，后续取消不撤销已发布不可变版本。

回测提交与训练启动检查的是满足本次需求的就绪版本，不是任务进程退出码或通用队列的 `succeeded`。工作台继续允许查询未就绪的数据任务结果，但不创建可执行实验数据版本。

`wait_ready` 等待超时或等待方取消，仅停止该次等待。调用方须明确调用 `cancel_prefetch` 才取消其请求。另一个消费者仍需要的共享采集不能被一个等待方取消。

首期库调用的任务句柄与执行进度由 `MarketData` 实例管理，生命周期限于所属进程；请求发布资格与取消记录写入模块目录，以便发布事务核对。关闭实例停止提交并收尾工作，不恢复未完成的过程内句柄。模块不另建持久调度服务。工作台继续使用已有持久任务记录和进程监督，重启后按照现有中断处理显示状态；已就绪版本始终可以重新解析和读取。

## 缓存获取与来源切换

一次预缓存先校验需求并检查本地覆盖与质量。已有数据满足需求时直接生成或复用就绪版本，不要求联网来源可用。只有真实缺口或 `refresh=True` 才检查来源能力并生成获取计划。有效缓存优先复用，仅获取缺失范围；显式刷新重新获取并发布新版本。已导入且覆盖完整的分钟数据在没有联网分钟适配器时也必须能就绪。

覆盖依据交易日历、交易时段及有证据的上市和停牌状态判断。只检查最早与最晚日期不足以确认完整；未知的中间缺口不能通过填零、前向填充或生成交易状态消除。研究组装层采用的假设单独披露，不能替代缺口证据。

来源优先级、超时、重试和并发限额由模块配置。自动切换仅允许具备所需能力、字段和相容价格口径的来源。请求中的普通消费者参数不选择供应商或文件路径；管理员通过模块配置调整来源策略。

来自不同来源的重叠区间必须先比对标准字段及价格口径。标准化后相同记录可复用；不一致形成冲突并阻止自动拼接。显式刷新使用一个来源取得所需完整序列后，可以发布携带差异记录的新版本。获取失败不导致旧版本被覆盖。

前复权等可能修订历史的来源不能仅追加末尾日期：若因子、锚点或上游历史发生变化，必须刷新受影响的已知历史，再发布一致的版本。无法确认复权一致性的响应保留为独立研究口径，按质量要求决定能否用于请求。

腾讯适配器保留实际返回的 `day` 或 `qfqday`、窗口重叠冲突和单位证据，不能因为请求参数为 `qfq` 就把所有返回值标记为已验证前复权。AKShare 是访问包装层，来源记录还须标注实际上游。

## 异步与并发

同步和异步入口复用一套获取、覆盖与发布逻辑。阻塞 SDK 和文件读取在有界线程执行；异步调用不在事件循环中执行网络请求、`time.sleep` 或大文件读取。超时与重试等待有明确边界，批次读取只按消费者需求预取有界数据。

相同完整需求与刷新策略的并发请求共享一次实际准备；每个调用方仍有独立请求状态和取消权。不同范围的请求首期通过序列级互斥，在获得所有权后重新检查覆盖，避免再次下载已补齐的区间，不额外设计复杂区间合并调度器。

多进程写入使用 SQLite 租约及发布事务：锁带所有者、过期时间和单调代次；续租失败或失去所有权的旧工作者不得发布。取消与发布检查进入同一事务，不能只依赖内存中的任务集合。共享工作全部请求取消后停止后续请求与发布；已开始的阻塞调用可能持续到超时，晚到结果不能发布为这些请求的就绪版本。

批次读取固定输入清单，按明确排序合并片段。返回 Arrow 批次便于训练层转换为数组；不要求一次加载整个行情库，也不在模块内生成全部重叠训练窗口。

## 工作台与历史数据接入

工作台的数据获取任务负责将 API 参数转换为 `DataRequirement`，在现有工作进程中调用模块并转发进度和取消。它不构造供应商、不指定原始缓存名称、不重新实现重试和单位转换。

模块取消与行情快照发布以模块目录事务为线性化边界；工作台取消与回测集登记以现有任务数据库事务为另一边界。工作台取消先提交时，必须阻止对应回测集登记；取消信号尚未传到模块时，模块可能已经发布完整行情快照，该快照可留供其他请求复用，但不能让已取消的工作台任务或实验变为就绪。这两个数据库之间不声称存在分布式原子事务。

模块返回就绪行情快照后，回测数据组装层通过 `read_bars` 与 `read_table` 构造并校验现有六张基础表及辅助表，冻结研究假设和策略资格规则。只有这个完整回测集也满足本次实验要求时才登记数据版本；模块的价格快照就绪不能跳过回测集验证。

工作台保存模块版本引用与组装后数据版本之间的来源关系。现有运行快照继续固定策略、配置、环境和数据摘要；读数据时按已有全历史规则转换为日线 `DatasetBundle`。本次不改变收盘信号、次日开盘、结算、公司行动与指标定义。

行情缓存属于 `quanto.data`；回测组装产物和运行快照仍属于工作台。现有内容寻址和哈希校验逻辑在数据模块中复用，避免两个独立行情缓存实现。已有历史对象继续按原引用读取，不增加用于维护旧采集 API 的兼容层。

遗留 CSV、已有 Parquet 和供应商专用目录通过显式导入进入统一存储。导入保留原文件哈希、来源、单位和限制，不能推断缺失证据；原目录保留为历史输入，不再接收新采集。新采集脚本只能使用模块入口。

## Git 与备份

新的完整行情库与原始响应使用已配置的数据根，不进入普通 Git。仓库保存契约、配置样例、版本清单格式、采集代码和小型测试样本。现有已跟踪冻结研究数据保留，不在本次重写 Git 历史。

备份必须包含目录、版本清单、被引用行情片段和来源证据；只备份 SQLite 或只保留数据版本 ID 不足以复现。模块及工作台记录引用后，不得删除仍被引用对象。

## 验收与测量

先按当前需求审查相关测试，删除对旧路径、随机缓存名和旧采集函数的实现绑定，保留有效的数据语义、取消、覆盖及复现验证。不得增加旧 API 适配层仅用于通过旧测试。

| 场景 | 验收结果 |
| --- | --- |
| 两个完全相同需求重复执行 | 第二次零上游请求，复用相同快照，默认不生成新缓存身份 |
| 请求扩展或存在中间缺口 | 只补真实缺口；不完整响应维持未就绪 |
| AKShare 与腾讯切换 | 同一公开契约和存储结构；来源及实际价格模式可追溯，无新增来源目录 |
| 来源单位或复权不相容 | 不自动拼接；明确质量问题或冲突，旧版本内容不变 |
| 异步预缓存遇到慢响应 | 事件循环可继续工作；超时、进度和状态可查询 |
| 多个等待方及跨进程竞争 | 共享获取或锁后复查；一方取消不影响另一方，无重复或失效所有者发布 |
| 模块发布前取消或进程中断 | 对应请求不就绪；允许留存完整但未引用的对象 |
| 工作台取消与行情发布竞争 | 工作台任务不登记可执行回测集；已发布行情快照可以继续复用 |
| 无网络环境读取已就绪版本 | 回测与批次读取成功，适配器调用次数为零 |
| 完整分钟导入但无联网分钟适配器 | 预缓存正常就绪，未调用任何来源 |
| 参考表与辅助表查询 | 只使用公开读取接口，不依赖物理目录；超范围拒绝且不联网 |
| 运行读取超出声明范围或文件篡改 | 在计算前拒绝，不尝试联网补齐 |
| 日线与分钟导入往返 | 类型、前导零、时区、区间边界、单位及全局批次顺序一致 |
| 有证据的停牌或上市边界 | 覆盖校验按证据通过；未知缺口不通过 |
| 当前日线回测接入 | 预热前历史、累计资格、后继日历、跨边界事件和辅助信息可得性保持正确，订单与报告等价 |
| 刷新与旧实验重跑 | 刷新发布新版本，旧实验继续读取原字节 |
| 任务正常退出但数据不完整 | 通用任务完成不触发回测启动，不登记可执行数据版本 |

离线测试使用两个假来源和固定日线、分钟样本；腾讯响应解析测试使用已保存的小型响应样本，不依赖实时网络。必要的人工真实源验收另行记录来源、请求时间、范围、缺口和质量限制，不以一次成功推断长期历史能力。

容量和性能测量分别记录：重复预缓存请求次数、补缺请求范围、新增文件字节、完整与筛选读取、批次内存峰值、版本校验开销和工作台端到端准备时间。以代表性日线与分钟样本比较，不能将文件格式微基准直接称作整体回测速比。

## 实施顺序与完成边界

后续实施计划按契约与目录、统一存储和离线读取、来源接入、同步与异步预缓存、工作台接入、导入和研究脚本收口划分可独立检查的阶段。每阶段完成适用验证后立即本地 commit，仅暂存该阶段相关文件，不 push。

本设计不会改变已运行预览的配置或迁移其工作区。数据根通过明确配置接入。

设计审阅后再编写包含文件、测试和阶段提交的实施计划。实施完成必须同时满足统一源结构、跨任务缓存复用、异步预缓存启动条件、运行纯本地读取及既有日线语义验证，不能仅以新增接口或目录作为完成依据。
