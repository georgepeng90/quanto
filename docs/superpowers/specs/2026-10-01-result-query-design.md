# 回测结果查询与展示设计

## 问题与目标

旧详情页串行读完每张表的分页，再等待 12 张表全部完成后渲染。长回测持仓表可达数万行；每页还重复解析 CSV。请求失败和正在加载均被显示成“无数据”。

改为轻量总览、服务端索引查询、明细按需取页。浏览器初次进入不下载完整持仓或交易历史，任何明细请求至多 100 行；加载失败明确展示并可重试。

## 存储与完整性

- 已发布的 CSV、JSON、HTML 是完整且冻结的研究产物，继续用于导出和来源校验。
- 为每套已验证产物按内容哈希懒建立 SQLite 查询副本，存于工作区 `result-indexes/`；它属于可重建的派生数据，不能修改冻结产物。
- 导入逐行处理，保存类型化 JSON 和查询字段，建立日期、标的、订单关联索引。查询使用 SQL 筛选及 LIMIT，不在 Python 或浏览器加载全表再切页。
- 并发首次访问只发布完整索引，后续进程可复用。仍检查源产物内容哈希，文件同大小且恢复时间戳的修改也必须被拒绝。
- 不再保留整张表的 Python 内存缓存。图表摘要按参数存于查询副本，缓存有明确条目上限。

## 接口

- `GET /runs/{id}/tables/{name}`：`cursor`、`limit`（1–500，页面使用 100）、`date_from`、`date_to`、`symbol`；返回 `items`、`next_cursor`、`total`。日期范围包含两端，修改筛选后从第一页开始。
- 上述接口的 `context_date` 仅用于单日追踪：订单含当日信号及执行订单；成交经 `order_id` 关联；策略和风控包含关联订单的信号日上下文。不得用当前页的订单推断整个上下文。
- `GET /runs/{id}/charts/{name}`：`curves`、`monthly_returns`、`annual_returns`、`allocation`，可选日期范围及 `max_points`（默认 1200）。返回 `items`、`total_rows`、`sampled`。曲线采样保留端点与极值，持仓图按日期与标的加工且限制总点数。
- 图表采样只用于显示，不据此计算收益、回撤等最终指标。完整明细经分页或导出访问。
- 非成功任务仍可以查看已完成交易日的部分记录，不构建最终索引或展示最终绩效。

## 网页交互

- 进入详情页只请求运行状态、近期日志、最终指标、当前图表、账户最新交易日的一页和最新日交易上下文；没有遍历所有表的循环。
- 切换明细页签才查询该表。可输入日期区间与标的，提交筛选后取第一页；上一页、下一页每次只请求一页，显示匹配总行数。
- 交易追踪默认最近完成交易日，可切换日期、标的；四类记录各自分页，跨信号日关联由服务端处理。
- 图表页签按需查询摘要，可选择查看区间。图表展开的数据明确标为图表数据，不能称为完整历史。
- 每块分别显示加载、失败、空结果。短暂网络/服务错误最多尝试三次；切换筛选、页签或运行立即中止旧请求，过期响应不能覆盖新内容。
- 对比图也读取摘要接口，不能继续下载每个运行的整条曲线。

## 验收

1. 数万行数据查询仅返回指定范围的当前页，SQL 使用筛选索引，重复分页不重新解析 CSV。
2. 初次详情访问和页签切换请求数有界；延迟持仓请求不影响曲线、账户或交易追踪。
3. 日期、标的、尾页、空页、跨信号日追踪、来源类型和产物篡改均有测试。
4. 曲线摘要不超过点数上限并保留首尾与大回撤；持仓摘要总点数有界；最终指标与导出不变。
5. 使用真实长回测实测冷启动、重复查询和响应规模，并在浏览器验证交互。阶段完成后分别本地提交，不 push。
