## 2. 当前实现：保留什么，问题在哪里

### 2.1 当前训练循环

```text
创建一次模型：固定 ETF、输入/动作定义、数据、日期和训练参数
    ↓
首次：随机初始化 PPO；后续：读取同一模型最近成功版本的 last.zip
    ↓
在训练期抽取历史片段 → 模拟交易 → 根据净值变化给奖励 → 更新权重
    ↓
按已有间隔，在验证期回测；严格超过本模型历史验证最佳才更新 policy.zip
    ↓
保存新版本：last.zip 用于继续学习，policy.zip 用于指定版本的推断/回测
    ↓
需要继续学习时，对同一个 model_id 追加训练步数
```

当前每个环境 step 对应一次周/月决策，内部逐日执行账户；奖励是该步账户净值比值的对数，已经包含实际交易成本。训练会话之间保留网络、优化器和累计步数，但重新建立环境、模拟账户及片段采样。它不是一条不断接续的实盘持仓轨迹，也不保证等于一次不中断长训练的精确重放。

创建模型时已可在“高级训练、成交与风险参数 → 随机种子”指定 `seed`；42 只是默认值，提交值会保存并用于首次训练，创建后随模型配置固定。本版沿用此能力和现有续训采样机制，不新增 seed 功能或指定试验必须使用 42。依据：[创建表单](../../../web/src/components/ModelCreation.tsx)、[配置定义](../../../src/quanto/investing/contracts.py)。

依据：[environment.py](../../../src/quanto/investing/environment.py)、[training.py](../../../src/quanto/investing/training.py)、[models.py](../../../src/quanto/investing/models.py)、[续训测试](../../../tests/unit/test_investing_continuation.py)。

### 2.2 2024 年的作用

已有固定篮子研究用 2022—2023 年更新权重，用 2024 年 Sharpe 选择权重。2024 年成绩不是逐步训练奖励，但反复根据这段成绩选模型、改奖励或调参数，会产生选择偏差风险。DSR 改变训练目标，不能单独消除该风险，也没有证据据此断言现有模型已经过拟合。[E3]

原奖励会惩罚亏损和交易成本，也有对数效用含义；不能称其“没有风险意识”。DSR 要试验的是另一种风险调整收益目标，不是修复一个已证实错误的收益公式。[E1、E4]

历史研究的 2025/2026 年成绩已经查看，ETF 篮子也使用了 2026 年评级回溯选择。后续继续使用这些历史可以做开发比较，但不得重新称作从未接触过的盲测，更不能宣称已经覆盖完整经济周期。依据：[历史协议](../../research/2026-10-05-fixed-basket-training/protocol.json)。

### 2.3 本次改为近期成绩选优

新对照和 DSR 在训练中挑选 `policy.zip`、以及最后比较两种奖励时，统一使用事先确定的最近一年或两年区间。该区间在程序中就是验证期：训练期只负责 PPO 更新，验证期回测负责选优。保留 `validation_sharpe` 指标，改变它所评价的日期；不再先用固定 2024 年挑权重，再把近期回测仅作为展示。

近期区间一旦用于比较和选择，就属于开发验证数据。改用较近行情能让选优依据更贴近当前数据，但不能据此宣称消除了选择偏差。2024 年旧分数只保留为历史记录；最近两年自然覆盖到的 2024 年末数据仍可属于新区间，并不要求剔除所有 2024 年交易日。

## 3. RL、PPO 与同模型持续学习

### 3.1 PPO 在同一个模型里做什么

1. **观察：**读取截至当前决策日可知的行情特征及账户状态。
2. **行动：**当前策略产生持仓动作；训练时会按策略分布采样，回测通常使用确定性动作。
3. **得到反馈：**交易由账户执行，随后产生净值变化；奖励函数把结果转换为学习信号。
4. **收集一批经历：**保存观察、动作、奖励及相关预测。项目的 `n_steps` 是决策步数，不是新增交易日数。
5. **更新：**PPO 用这批经历估计动作比预期好或差多少，更新策略网络及估计未来奖励的价值网络。概率比裁剪用于限制部分过大的策略变化，不保证每次更新都提高真实收益。
6. **再采样：**用更新后的策略重新走训练环境，再做下一批更新。`n_epochs` 是对这一批样本做多少遍优化，不是产生几个模型。[E2]

因此“一次训练”本身已经有大量尝试和更新，后续训练继续改变同一个模型的权重。

### 3.2 沿用同模型续训和一个评价区间

同模型续训就是加载最新 `last.zip` 后追加 PPO 更新。模型从版本 1 续训到版本 20，仍是一条学习链；本版保留这套已有流程。

一份训练数据可以包含多年的行情，片段采样仍从这一个训练范围内抽取经历。近期一年或两年则作为一个连续评价区间，不按年份拆开选优，也不把一年、两年各跑一遍后挑更好的结果。对照与 DSR 各保留一条模型链，只比较奖励方案。

### 3.3 “不断训练”不等于“不断进步”

同一历史数据可以反复学习，但没有因此增加新的市场信息。更多更新可能帮助优化，也可能强化历史噪声；市场关系变化后，旧经验也可能不再适用。

现有 `last.zip` / `policy.zip` 分离有实际作用：最新权重继续探索，历史验证最佳权重可以保留。新试验在同一个固定近期区间内保留验证最佳；分数不下降只是同一选择标准下的保留机制，不能保证未来收益不下降。训练奖励与真实回测成绩要分别观察，不能用“累计训练步数更多”代替效果证据。

### 3.4 学习新增行情：方向合理，当前尚不支持

目前同模型续训要求数据内容哈希、日期和配置不变；训练请求只允许追加步数和选择设备。因此当前支持的是“旧数据上继续优化”，不是“行情每天增加，旧模型自动吸收”。[代码：training.py、models.py]

已有策略在新行情上回测是现有能力，只要满足篮子、价格模式和日期等约束；回测不会让策略学习这些新行情。

真正加入新行情后的连续学习应遵循：保存旧版本 → 明确新一轮能学习的数据与留出的评价数据 → 继承旧权重并在更新后的训练环境重新采样 → 更新权重 → 在同一评价条件下比较新旧版本 → 决定使用哪个版本。不同轮次、不同日期算出的 Sharpe 不能直接拿来沿用历史最佳分数。

这不必从零随机初始化，也不必在产品概念上变成另一套策略。论文 E1 的实验就使用过跨年度继承已学参数的方式，但不是本项目的 PPO 实现保证。工程上还需定义数据版本、训练范围、优化器处理和新旧版本比较；不能只删除现有数据一致性检查。

**本版边界：**先使一条 DSR 模型链能够按当前方式正常续训并验证其价值。跨数据续训属于后续独立设计；本版完成后不会将它标为已支持。如果目标包含持续吸收新增行情，仅完成本版还没有达到全部目标。

## 4. DSR 奖励的可执行定义

### 4.1 固定的三个方案

在 `PolicyTrainingSpec` 增加一个创建后固定的 `reward_version`，不增加通用奖励插件系统。省略字段时明确按现有净对数收益处理，以保留已存在模型的训练/回测语义。

| `reward_version` | 奖励 | 网络输入 | 用途 |
| --- | --- | --- | --- |
| `net-log-return-v1` | 现有净对数收益及现有首步区间语义 | 原 `12 × ETF数量 + 4` 维 | 现有模型保持原行为 |
| `net-log-return-with-state-v1` | 动作后区间的净对数收益 | 原输入再加下述 A、B 两项，共 `12 × ETF数量 + 6` 维 | 与 DSR 做公平对照 |
| `differential-sharpe-v1` | 动作后每日 DSR 之和 | 与新对照完全相同 | 本次候选奖励 |

为什么需要新对照：DSR 依赖收益历史统计，当前使用的前馈 `MlpPolicy` 不保存这两个量。把它们提供给策略后，不能把“新输入加新奖励”的效果全部归因于奖励。两个新方案使用相同输入、网络形状和统计更新，只改变优化目标；旧模型作为历史背景保留。

第一次试验创建两个模型：新对照和 DSR。此后各自使用原有 `model_id` 续训；不是每轮创建模型。旧模型输入维度不同，不能自动补零迁移权重，也不能把旧收益目标与新 DSR 训练记录悄悄混在同一学习链中。本版不实现旧权重向新输入结构的迁移。

### 4.2 每日更新的公式

两个新方案每个交易日收盘读取共享账户权益 `E_t`，以此前收盘权益计算净简单收益 `R_t = E_t / E_(t-1) - 1`。该净值已经计入实际成交、成本和账户现金流，不再额外扣一次手续费。首次每日计算以初始现金为前值。

DSR 计算顺序如下；A 是收益的一阶指数移动矩，B 是二阶指数移动矩，不是波动率本身：[E1，§2.2]

```text
delta_A = R_t - A_previous
delta_B = R_t² - B_previous
variance = max(B_previous - A_previous², variance_floor)
D_t = (B_previous * delta_A - 0.5 * A_previous * delta_B) / variance^(3/2)
A_t = A_previous + eta * delta_A
B_t = B_previous + eta * delta_B
```

必须先用旧 A/B 算 D，再更新 A/B。D 是局部风险调整收益变化的信号，不是报告里的 Sharpe；未触发方差下限时，相关一阶近似是 Sharpe 变化约为 `eta × D`。本版使用 D 本身，不再乘 eta；奖励之和也不等于年度 Sharpe 或账户收益。

奖励正负取决于已有收益与波动状态，不能解释为“每次赚钱都必定奖励、亏钱都必定惩罚”。初值、方差下限和有限历史会影响表现；DSR 不是收益最大化、回撤限制或防过拟合的保证。

### 4.3 首版工程常数和适用范围

| 项目 | 固定值/规则 | 理由及限制 |
| --- | --- | --- |
| `eta` | `0.01`，按交易日更新 | 约百日量级的衰减记忆，不是硬截断窗口；不是 PPO 学习率或 gamma |
| 初值 | `A_0 = 0`，`B_0 = 0.0001` | 零均值、约 1% 日波动的先验；避免零方差起步；不是从未来数据估计 |
| `variance_floor` | `1e-8`，只用于 D 的分母 | 避免近零分母；触发时不再是未正则化 Sharpe 的严格导数 |
| 数值 | A、B、收益及 D 用 float64 | 非有限值或非正权益明确失败；不把异常置零后继续 |
| gamma / 无风险收益 | 两个新方案限 `gamma=1`、`backtest.metrics.risk_free_rate=0` | 不在本次试验引入可变步长折扣或超额收益换算；既有方案的配置范围保持原样 |
| 额外塑形 | 无 DSR 裁剪、收益混合、额外回撤/换手罚项 | 首次只检验一个目标；现有仓位/风控和账户成本继续生效 |

这些数值、先验、限制和工程处理均是本项目可审查的试验起点，**不是论文证明的最优参数**。先通过有限值与极端序列检查，再作有限预算训练；若低方差后出现尖峰或训练不稳定，记录失败并修改设计，不通过悄悄裁剪或扩大奖励组合掩盖问题。不做参数网格搜索。

### 4.4 时间边界、重置与可见状态

1. 在 `advance_to_close()` 每次返回收盘账户状态后流式计算日收益和 A/B。训练通常 `collect=False`，因此不能依赖事后导出的 `result.equity` 表计算训练奖励。
2. 周/月动作频率不变。一个动作后的每日 D 累加到下一决策日或期末，作为这个环境 step 的奖励；不按天数取平均，不把一周的复合收益当作一次日收益。对照方案在同一区间累加每日 `log(1 + R_t)`。
3. `reset()` 会先自动持有现金推进到首次决策日。这段尚无策略动作的日收益更新 A/B，但不把其奖励归给第一个动作；单独记录其真实对数收益作为 `prefix_net_log_return`。两个新方案边界一致；旧方案保留原首步包含前缀的语义。
4. 每次 episode 重置账户时也恢复 A/B 先验；跨决策、rollout 和 PPO 更新不重置。续训会话仍沿用现有新环境重置行为，不能将上一片段的 A/B 接入随机抽到的另一片段。
5. 决策时的 observation 增加 `A / (0.01 + abs(A))` 和 `B / (0.0001 + B)`，使用截至当时已发生的收益。它们有界，最后才转 float32；不读取动作之后的数据。两个新方案共享同一个新特征版本；ETF 顺序和动作空间不变。
6. 验证/回测也按相同时间顺序更新 A/B、构造输入；仅不执行 PPO 更新。不能在训练提供 A/B，推断时却填零。未来交易接入也要维护这两个账户统计状态，不是只加载网络文件就足够。

### 4.5 实际收益必须与学习奖励分开

当前 `evaluation.py` 断言 `sum(reward) == log(final_equity / initial_cash)`。这只适用于现有奖励，不能原样用于 DSR，也不能直接删除账本检查。

环境应分别提供学习奖励和实际收益信息。新方案在 reset 返回前缀真实对数收益，在每个 step 的 info 返回 `step_net_log_return`；评价器核对：

```text
prefix_net_log_return + sum(step_net_log_return)
    == log(final_equity / initial_cash)
```

旧方案沿用其包含前缀的步收益账本关系。两个新方案还需输出奖励总和、DSR 最大绝对值、方差下限触发天数/总天数；训练仅累积轻量统计，不为此打开全部逐日表收集。相关统计分别标明训练/评价及会话范围，不能把多个会话的重复历史天数称为新行情数量。

收益、Sharpe、回撤、换手和成本继续由现有真实账本报告计算。`training_reward_sum`、`evaluation_reward_sum` 只用于同奖励版本诊断，不能跨奖励公式比较，更不能显示为盈利。选权重统一使用第 6.1 节近期区间的 `validation_sharpe`，不以 DSR 总和或固定 2024 年分数选优。

## 5. 参数归属与每步输入输出

配置仍存在已有 `PolicyTrainingSpec` 中；下表区分含义，不要求新增一套存储层。

| 归属 | 内容 | 能否在同模型续训时修改 |
| --- | --- | --- |
| 模型直接定义 | ETF 清单及顺序、输入定义、动作含义、周/月频率、网络结构、`reward_version` 及其固定常数 | 不能；DSR 增加状态输入不改变 ETF 池 |
| 训练计划 | 数据版本、训练/近期验证日期、可选留出测试日期、片段长度、PPO 学习参数等现有训练配置、验证间隔和选模指标、账户假设 | 同链固定；可选测试期是本版待实现改动，不代表当前 API 已支持 |
| 一次训练请求 | `additional_timesteps`、`device` | 可以；服务端自动选择同模型最近成功父版本 |
| 环境运行状态 | 当前持仓/现金、当日权益、A/B、片段位置 | 由模拟过程更新；不是用户输入的超参数，也不是网络权重 |
| 一次回测请求 | 固定版本、数据、起止日期、基准和成本倍率 | 按已有接口提供；不修改被回测模型定义 |

| 步骤 | 输入 | 输出 | 更新网络吗 |
| --- | --- | --- | --- |
| 创建模型 | 固定模型定义和训练计划 | 一个 `model_id` | 否 |
| 开始/继续训练 | 模型配置、数据、预算；续训时有 `last.zip` | 当前训练状态和新模拟环境 | 初始化/恢复，尚未优化 |
| 交互与奖励 | observation、动作、随后实际每日净值 | 下一 observation、学习奖励、独立的实际收益及诊断信息 | 否 |
| PPO 更新 | 近期 rollout、策略/价值网络和优化器 | 新权重、优化器状态和累计步数 | 是 |
| 验证选权重 | 当前权重、固定的近期验证数据和账户规则 | 账本指标、选择记录、可能更新的 `policy.zip` | 否 |
| 保存会话 | 最新训练状态、验证最佳及其来源 | 新版本中的 `last.zip`、`policy.zip` 和清单 | 否 |
| 后续时期回测 | 明确版本、允许的后续行情区间 | 独立的收益/风险报告 | 否 |

奖励版本、实际常数、输入版本必须记录在现有清单并参与身份检查。保持已有模型和产物哈希不变；旧清单缺少奖励字段时按明确的旧公式解释。拒绝跨奖励版本续训，不新增任意模型加载或权重迁移接口。

特征和环境身份按奖励方案派生，由训练和回测共用同一规则：旧/省略奖励版本继续使用当前依 lookback 确定的特征版本及 `daily-session-v1`；两个新方案共用新增收益状态的特征版本和环境版本，奖励版本另行区分。不能全局替换版本常量而使旧模型被拒绝；旧清单只在读取后补充解释，不改写原文件和哈希。

## 6. 首次试验与之后的日常使用

### 6.1 近期评价区间的确定

1. 开始试验前，取所用数据集中固定 ETF 篮子共同可用、已完成且覆盖核验通过的最新交易日为截止日 `T`；不直接拿电脑日期充当行情截止日。
2. 本稿默认最近两年；也允许在开始训练前明确选择最近一年。按自然年回溯，区间为 `(T 减 N 年, T]`，`N` 只能预先选定为 1 或 2；左侧周年日若为无效日期则取该月末日。实际回放使用该区间内交易日，不能看完结果后换长度、平移截止日或挑子区间。
3. 将这个唯一的近期区间写为 `validation_start` / `validation_end`。训练结束日严格早于它；特征预热可以读决策日之前的历史，但不能把评价期收益拿去做 PPO 更新。
4. 同次对照、同链各轮续训均固定数据、起止日期、成本、初始现金和 `validation_sharpe`。每次评价从相同初始账户及 A/B 先验开始。普通续训不会随日历自动移动窗口；更换数据或评价日期属于第 3.4 节的后续设计，旧分数不能直接作为新窗口的历史最佳。

按[现有数据核验记录](../../research/2026-10-05-fixed-basket-training/data-freeze.json)的 `T = 2026-09-30` 举例：

| 预先选择的长度 | 近期选优区间（含首尾日期） | PPO 训练结束日上限 |
| --- | --- | --- |
| 两年（本稿默认） | 2024-10-01 至 2026-09-30 | 2024-09-30 |
| 一年（替代选择） | 2025-10-01 至 2026-09-30 | 2025-09-30 |

这是二选一的日期说明，不是两组实验任务。启动时必须重新核查实际数据截止日和特征预热覆盖；数据不足应明确报错，不能悄悄缩短区间或退回 2024 年。

### 6.2 近期验证与留出测试的接口边界

当前 `PolicyTrainingSpec` 强制训练、验证、测试三段日期依次分离；普通 `backtest_policy()` 也要求请求起点晚于 `validation_end`。如果验证期用到最新数据 `T`，现有数据就没有更晚的测试段。只改日期配置无法满足本设计，不能编造未来测试日期或把验证期重复填成测试期。

最小配套改动是让 `test_start` / `test_end` 成对可选：都不填时仅检查训练、验证的顺序和覆盖，`backtest.end` 取 `validation_end`；都填写时保留现有测试期顺序与覆盖检查；只填一个明确拒绝。历史模型的既有日期和清单保持不变。

数据检查只遍历实际存在的分区，不为缺省测试期调用 `split_spec()` 或创建环境。训练结束后仅在设置了测试期且请求评价测试时才执行该段；否则 `metrics.test` 保持空值，清单不得声称已评价测试。模型产物的 `cutoff` 仍为 `validation_end`。本次试验不设置留出测试期，也不自动追加测试回测。

训练中的近期回测继续走 `evaluate_policy()`。最终对比读取各自选中的 `policy.zip`，用相同评价器在同一期限输出完整收益、风险和账户报告，并明确标为“用于选优的验证回测”；不能拿最近 `last.zip` 的成绩冒充最佳权重成绩。保留普通后续回测的日期隔离，不通过放开其截止日检查来伪装独立测试。

创建表单允许省略留出测试期，详情页显示“未设置留出测试期”。普通后续回测表单不把验证日期自动填成测试日期；无留出日期时清空日期，只有后来具备符合截止日约束的数据和请求时才执行。近期验证报表复用既有评价器及报告格式，不建设第二套回测引擎或实验平台。

### 6.3 首次试验：同一期限、两个奖励方案

1. 开始前用普通说明文件记下数据版本、共同截止日、唯一评价区间、训练日期、训练配置、相同会话划分和有限预算。保留固定 ETF 池；不搜索日期，也不新增协议平台。
2. 用相同 ETF、数据、日期、账户、现有训练参数、两项新增输入和验证规则创建新对照与 DSR；两者都按已有首次训练流程初始化。旧模型仍可使用，但不沿用它的 2024 年最佳分数作为本次门槛，也不修改旧模型的冻结配置。
3. 两者分别从自己的 `last.zip` 续训，按相同近期验证 Sharpe 保留各自 `policy.zip`。报告实际完成步数；PPO 完整 rollout 可能影响实际步数，不能只比较请求值。保留失败、取消及未完成记录。
4. 在同一区间比较两个选中版本的 Sharpe；收益、回撤、换手、成本、现金比例及训练稳定性一并列出，不组合成质量分。相同验证成绩不触发权重替换；数值异常或训练失败不算有效胜出。结论只适用于本次配置和区间，不能用训练奖励总和替代真实绩效。

不分多个时期补测，也不要求从头训练“最终模型”。若 DSR 没有改善，就记录本次未见改善；若数值不稳定或证据不足，就记录限制，不靠继续试到好结果宣布通过。近期成绩用于选择，不能再作为独立样本外证明。[E3]

### 6.4 若决定采用 DSR，日常仍是一条训练链

```text
DSR 模型 M，第 1 版
    → 读取 M 的 last.zip，追加训练 → 保存 M 的第 2 版
    → 读取 M 的 last.zip，追加训练 → 保存 M 的第 3 版
    → 按同一方式继续；验证不足以支持更新时保留原最佳 policy.zip
```

继续这条 DSR 训练链，在创建时固定的近期区间比较版本。需要使用模型时，指定一个有效选中版本及其配置；继续研究不会自动替换已指定的使用版本。交易执行接入仍是另一个任务。

### 7.2 必须通过的检查

| 验收 | 可检查结果 |
| --- | --- |
| 公式顺序 | 初值下日收益 +1% 时 D=1、A=0.0001、B=0.0001；多步例子与独立手算一致，能识别先更新 A/B 再算 D 的错误 |
| 时间与因果 | 固定同一净值路径及前缀截止点，仅重分组后续每日收益时，A/B 和 D 累加不变；尾部短周、现金前缀、片段末日不遗漏/重复；未来价格不改变更早的输入 |
| 状态与输入 | 相同 episode、动作及净值路径下，两个新方案逐日状态和输入一致；reset 先恢复先验再处理前缀，返回前缀更新后的状态；rollout 不重置；训练/推断同维同义，旧模型仍原维度 |
| 数值 | 全现金、长零收益、单次冲击、正负交替均有限；非正权益/非有限值失败；方差下限触发有记录，不断言 DSR 必定降低回撤 |
| 账本 | 含成本和现金前缀的真实对数收益与终值相等；DSR 总和不用于该等式；真实报告指标不因奖励标签被替换 |
| 续训 | 同一个 DSR ID 恢复自己的网络/优化器/步数；新会话按现有约定重置环境；改奖励、输入或数据被拒绝；缺少奖励字段的旧清单仍可加载、回测及续训，原文件/哈希不变 |
| 选模与隔离 | 新试验明确使用近期区间的 Sharpe；验证评价不更新权重；训练采样不进入评价期；若有更晚测试期，其价格不能改变训练或验证选择；奖励诊断及旧 2024 年分数不成为选模依据 |
| 日期与报告 | 用数据共同截止日推导一年/两年区间，检查非交易日边界和覆盖；仅执行预选的一段；报告记录实际日期和选中版本；同链固定日期，拒绝跨窗口沿用旧最佳分数 |
| 可选测试期 | 无测试期可以创建、训练、续训，覆盖截至验证末日，不创建测试环境且测试指标为空；只填一个、日期重叠或超出覆盖均拒绝；有测试期和旧模型仍按原日期约束；普通回测仍拒绝验证期内请求 |
| 用户界面 | 创建请求正确发送奖励版本和可选测试日期，详情显示实际验证期及未设置测试期的状态；无测试期时不自动用验证期填充普通回测；正常续训不要求重建模型 |

本阶段是文档修订，以上是未来实现的验收要求，不是已通过的产品测试。实施时先审查既有 reward 等式及日期测试：旧奖励的账本等式仍有效；新奖励使用独立收益检查；“必须填写测试期”的断言按新需求更新，不为旧测试强制制造额外区间。

## 9. 修改后的完整大循环与当前的区别

| 步骤 | 当前 | 本版实施完成后 |
| --- | --- | --- |
| 1. 定义模型 | 固定 ETF、输入动作、数据和 PPO 参数 | 保留；选择固定奖励方案和近期验证区间；可不设留出测试期 |
| 2. 开始/继续 | 首次初始化，以后从同 ID 的 last.zip 恢复 | 相同；已有模型不自动迁移到 DSR |
| 3. 回放历史、模拟交易 | 周/月动作，内部逐日记账 | 相同；新方案同时逐日更新两个收益统计量 |
| 4. 反馈给 PPO | 净对数收益 | DSR 模型使用每日 DSR 累加；新对照仍使用净对数收益 |
| 5. 更新权重 | PPO 采样、优化、再采样 | 相同；每种奖励只训练一条模型链 |
| 6. 验证与保存 | 固定验证期选 policy；既有研究用 2024 年 | 新试验以固定近期一年或两年 Sharpe 选 policy，保存 last 供续训；奖励与绩效分开记录 |
| 7. 判断模型优劣 | 既有研究另看 2025/2026 年报告 | 两奖励选中版本在同一近期区间比较，标明已用于选优；不做分时期补测 |
| 8. 再训练 | 同一 ID 在同一数据上追加步数 | 相同；沿用现有续训机制，评价日期保持固定 |
| 9. 行情数据增加 | 不能在同一冻结配置上直接继承旧权重续训 | 本版仍未支持；需要独立解决跨数据续训，不用重新随机训练冒充持续学习 |

实际增加的是一种学习目标及必需的状态和诊断，并将新试验的选优依据改为一个固定近期区间。日常主循环仍围绕同一模型的多个版本展开。
