# Agent 个股研究与筛选设计

## 用户意图与前置条件

用户希望由 Agent 根据在线个股信息、公司财报和资讯，先筛选一批合适股票，再交给强化学习使用。已确认首版为“量价训练＋公司资讯选股”，不把财报或新闻直接加入 RL 观察空间。

本设计是待实施方案。[个股训练接入](2026-10-13-stock-training-design.md)先完成；选股模块随后通过现有股票组合、数据检查和模型入口交付候选。不能以“保存了股票池”表示“训练已经就绪”。

## 模块边界

新增独立 `quanto.screening` 领域模块，提供结构化研究输入、确定性筛选、结果保存和训练交接。外部 Agent 通过 API/CLI 检索资料、整理证据、提交公司研究；项目不内置新的通用 Agent 运行平台、不托管模型密钥、不在训练进程中联网研究。

数据获取、筛选计算、Agent 判断和训练执行分开记录：

1. 结构化基础数据确定研究范围和规则初筛结果。
2. Agent 阅读有来源的材料，提出公司入选或排除理由，并记录反面证据和未知事项。
3. 服务端核验身份、来源引用、时间、数值及规则结果，形成一次不可变筛选记录。
4. 经明确的交接操作创建股票组合，检查具体训练配置；提交训练仍使用现有接口。

首版以从当前时点开始的研究记录和后续评估为目标。自由联网的 Agent 不提供“无未来信息的历史选股”模式。

## 筛选输入与规则

一次筛选请求明确：名称、筛选截止时间、基础股票范围、目标数量、上市时长及流动性条件、允许板块、风险排除条件、行业数量限制，以及研究目的。

各阈值由该次请求明确给出，不预设所谓最优数值。基础范围来自带日期的完整列表或用户明确提供的研究名单；自由搜索发现的公司必须标记为主观发现名单，不能宣称覆盖全市场。

首版规则限定为：

- 上市时间、证券和板块是否符合下游个股定义。
- 截止时间之前已完成交易日的平均成交额及有效历史长度。
- 来源明确的风险警示、停牌和退出状态。
- 每个行业最多入选数量及总目标数量。

规则使用结构化值进行计算。未知上市日、成交额单位不明、状态缺失分别产生“证据不足”原因，不转换为零、不自动视为通过。行业缺失也不能绕过行业上限。

Agent 只在符合规则的股票中提出顺序和理由；硬条件失败不能被自然语言推荐覆盖。行业约束按提议顺序确定性应用；同样输入和同样提议产生同样结果。允许少于目标数量或零入选，零入选时不创建空组合。

## 公司研究和来源证据

每只股票的研究包含：

- 明确证券身份、公司名称、业务摘要。
- 入选或排除建议、与研究目的有关的理由。
- 风险、反面证据、未知事项；事实与推断分别记录。
- 每条关键事实的证据引用，财务数值包含报告期、单位和口径。

来源记录包含 URL/文档标识、来源名称、原始材料或可复核摘录的内容哈希、发布时间、获取时间、适用证券及修订关系。只存一个链接不足以支持重放。缺少原文归档时明确标记为有限证据，不能宣称完整复现网页内容。

初次实现优先接受交易所、公司公告及正式财报；新闻可补充事件发现，但无法核实的报道作为待确认项。来源列表及其优先级在记录中冻结。网页或文档中的指令只视为材料内容，不能改变筛选规则、调用权限或提交训练。

Agent 自报置信度不解释为上涨概率。记录实际模型名称、提示模板版本和原始结构化输出；冻结结果保证能回放当次选择，不保证重新调用远端模型会逐字生成相同结果。

## 时间边界与评价用途

区分报告期、事件发生/生效时间、公开发布时间、获取时间和本次筛选时间。截止时间之后公开的材料不能进入该次筛选。只有披露日期时按明示的保守可用规则处理，不能默认开盘前已经知晓。

当前资料选出的股票可以使用过去行情训练量价模型，但这段行情的回测只标记为开发研究，不能成为选股有效性的样本外证据。下游模型保存筛选记录引用，报告保留选股时点，不能因为价格测试段晚于训练段就自动宣称盲测。

从真实保存的筛选记录开始向后评估。未来若新增历史重放，需要独立交付历史证券范围、退市证券、资料修订、历史可用性及大模型已有知识泄漏的处理方案；本轮不通过一个 `as_of` 参数假装解决。

## 持久化与训练交接

一次筛选保存完整输入、证据引用、Agent 提议、规则排除原因、最终有序成员和实现版本。重复提交同一幂等键及同一内容返回原结果；同键不同内容拒绝。记录不可原地覆盖，重新筛选产生新记录。

API/CLI 提供：提交筛选、列出记录、查看详情、导出结果、从结果创建股票组合。研究证据存工作区的内容寻址产物，数据库只保留索引与引用；沿用现有存储、原子发布和损坏检查惯例。

股票组合关联原筛选记录，并保留用户能理解的名称。最终成员顺序和冻结记录一致。下游数据缺口、定义不支持或配置不匹配时，保留筛选成果并显示训练阻塞原因；不能因能力检查失败而悄悄删除成员。

更换成员或顺序应新建训练模型。不得覆盖已有模型的股票池，也不自动启动昂贵训练或不停迭代筛选来追逐同一段回测成绩。

## 网页最小流程

增加“个股筛选”入口，展示筛选名称、时间、入选数量及状态。详情显示入选和排除理由、公司研究、可打开的来源、数据缺口，以及“用于创建个股模型”的下一步操作。

页面不展示修订号、哈希等内部字段作为主要操作项；这些信息留在来源详情和导出。先保证 Agent API/CLI 与网页共享同一结果，不另做两套筛选逻辑。

## 验收标准

1. 固定材料及 Agent 提议得到确定的筛选结果，能够导出并从冻结内容重放。
2. 错误证券映射、未来材料、缺失关键证据、重复证券、伪造来源引用和硬条件不满足被发现。
3. 目标不足、零入选、未知行业、矛盾资料、资料修订和同键重复提交均有明确行为。
4. 页面、API 和 CLI 使用同一份结果；网页显示真实状态与业务名称。
5. 结果→股票组合→能力检查→模型创建的成员、顺序和筛选来源一致；缺行情时不启动训练。
6. 历史开发回测不会被标为选股的样本外验证，筛选来源贯穿模型与结果导出。
7. 完成可复核的真实公开资料试运行；证据不能获取或数据不足时如实记录，不以合成示例替代真实验收。

效果研究单独比较“仅规则筛选”与“规则＋Agent 研究”，固定评价窗口、候选规模、交易成本和训练预算，报告不同随机种子及窗口的表现差异。软件闭环通过不等于选股策略有效。

## 可参考的数据来源

- [Tushare 股票基础信息](https://tushare.pro/document/2?doc_id=25)：证券身份与上市、退市日期；接口权限需按实际账号核实。
- [Tushare 利润表](https://tushare.pro/document/2?doc_id=33)：区分报告期和公告时间；有字段不等于已有完整历史时点数据。
- [巨潮资讯网](https://www.cninfo.com.cn/)：公司公告和财报材料。

这些来源仅作为接入候选，本设计不宣称已完成它们的批量采集或历史覆盖验证。
