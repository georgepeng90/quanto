# Agent 公司研究与个股筛选

先由 Agent 读取来源，提交结构化研究；后端不抓取请求中的 URL，也不解释材料中的指令。接口与网页共享同一份不可变结果。公司资讯不进入 PPO 观察空间。

```powershell
quanto --token $env:QUANTO_TOKEN screening submit --json examples/screening/public-information-request.json
quanto --token $env:QUANTO_TOKEN screening list
quanto --token $env:QUANTO_TOKEN screening show <id>
quanto --token $env:QUANTO_TOKEN screening export <id> --output research.json
quanto --token $env:QUANTO_TOKEN screening use <id> --name 公司研究组合 --key unique-handoff-key
```

`export` 默认拒绝覆盖已有文件；需要覆盖时显式指定 `--overwrite`。`use` 只创建组合，零入选拒绝创建。网页「个股筛选」可查看研究、排除原因和原始摘录，并把组合带到模型创建页面。模型仍须通过数据与定义检查，训练需另行提交。

请求示例中的公司资料真实，规则数值仅用于软件验收，不是经过研究的最佳阈值。示例是 **2026-10-13 已归档研究记录**，重新提交不会自动获取最新资料。实际研究须更新资料、时间和幂等键。

输入契约见 `src/quanto/screening/contracts.py`，或服务 `/openapi.json` 中的 `ScreeningRequest`：

- 明确研究范围是提供名单、主观发现还是带来源的全市场声明；后者仍是提交者声明，后端不保证其完整性。
- 规则显式提供板块、上市时长、成交额窗口和单位、历史长度、排除状态、行业数量上限及目标数。
- 候选记录覆盖提供的整个研究名单；未研究与不推荐者也保留。基础事实和每日行情必须引用已归档材料中的实际片段，引用证券身份必须一致。
- 价格、成交量和成交额必须有限且有效；日线仅使用声明日历中截止前完成的交易日。状态须覆盖最近完成交易日；缺行业、状态、上市日或行情不视为通过。
- 日历须延伸到筛选截止日期或之后的交易日，避免把旧日历末尾误当作当前最近交易日。股票范围的来源引用同样接受发布时间、获取时间及修订检查。
- 已知修订会使旧证据不可用；日期精度公告到下一交易日收盘才可用，缺日历或未知发布时间会阻止使用。材料获取时间也不得晚于筛选截止时间。
- 引用检查不等于独立验证 Agent 的事实提取、数值或全市场范围；`archive_level=excerpt` 仅表示有限摘录。对冲突材料，应引用修订后的证据或把事实标记未知后重新研究。
- 排名只作用于硬条件通过的候选，随后按行业上限与目标数筛选。少选和零入选均保存，不会放宽条件。

每条结果包括输入摘要、实现版本、所有排除理由、最终成员顺序及来源文本摘要。相同幂等键与相同内容返回原记录，改变内容须换键。筛选来源随组合、模型、冻结作业和回测归档，离线验证不依赖当前网页或工作区数据库；修改成员应创建新模型。

自由联网研究没有“无未来信息历史选股”模式。当前资料选择股票后用历史行情训练，仅作为开发研究；筛选时间与这一限制会进入结果。模型收益不证明 Agent 选股有效。

## 真实资料示例的边界

`public-information-request.json` 与 `public-information-result.json` 保存招商银行官方来源的少量检索索引摘录。直接读取部分官方 PDF 超时或没有正文，因此没有把摘录声明为完整原文，也没有从 URL 猜测发布时间。缺板块核验证据、交易日历、最新状态和量价历史，结果为 **零入选**，未创建组合或训练任务。这是对证据不足路径的真实试运行，不是完整真实股票数据验收。
